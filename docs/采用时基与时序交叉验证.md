# 采用时基与时序交叉验证（v8）

本轮根据[第八份复核意见](https://chatgpt.com/share/6aa7e186-f7a4-83e8-8cad-c7d07e02d3e1)
和用户提供的 `XT-STCAR_7d28761_review_reproduction.zip`，以提交
`7d28761c40f7d7e69a8ac77977f5b6710dd5a0c6` 为基线继续修正。
原复核只做了源码阅读及 Python 算术复算；本轮另行运行 Rust 测试和完整模拟，证据分别记录。

## 同一个实际采用时基

旧版导航以相邻规划间隔限幅，当前采用检查和证书以配置周期限幅，而输出线程以距离上次实际命令变化的时间限幅。
在规划 580→660 ms、实际采用 589→663 ms 时，80 ms 的规划间隔比 74 ms 的实际间隔长。
以 4 m⁻¹/s 为限，0.40→0.72 m⁻¹ 可通过旧规划却被输出拒绝。
这组曲率是独立材料构造的算术例子，不能冒充五次真实拒绝中的完整事件，也不能由它推断整场绕行根因。

`ExecutionHistory` 从同一份一致历史快照提供实际命令修订号、上次命令变化的采用时刻和持有目标。
`PlanningContext` 将其传入 `AdoptionConstraints`。导航在最早采用时刻，即规划窗起点，确定可执行曲率区间。
前置检查、最终证书和输出复核使用相同的时间定义；输出仍按真正的当前时刻及修订号复核。
同一命令重复输出不刷新时基；仅速度目标改变仍算一条新命令，与原输出端定义一致。
Stop 的目标曲率归零，实际模型转向继续渐变回中；后续恢复使用这次 Stop 的真实变化时刻。

正常导航在生成时避开不满足时基的候选。若手工 processor 绕过导航强行返回超限目标，
最终证书现在会提前拒绝，并沿既有证书失败策略输出普通 Stop；不能把这类回归写成“保持旧 Drive”。
真实控制器专项验证上次采用190 ms、本次规划/采用200 ms时区间为 `[0.36,0.44]` m⁻¹，
新合法Drive被采用后仍按其source100的原期限350 ms停车，而不是续租旧源。

未发生任何命令变化的启动状态保留原一周期起步限幅。缺失真实历史、未来时刻或修订号不一致不能借用启动规则。
不在 poll 中临时裁剪已认证命令，不延长源 lease，不让晚到 Drive 清除 Fault。
后备前瞻也跟踪模型中的命令变化时刻，包括仅改变速度的减速步骤；它不会重置当前真实源的历史 V/K 上界。

## 候选检查顺序

现在依次执行当前采用检查、原运动/停车/Grid/足迹 rollout、多源后备前瞻、终端认证与评分。
已被基础门拒绝的候选不会消耗后备前瞻；存活候选仍必须通过全部原约束才能入选。
rollout 只积分一次，原参考误差计算随积分完成，未降低采样、车体间隙或任何预算。

短路顺序改变会影响首个拒绝原因和累计工作量。这些是预期诊断差异，不能直接当成动作差异。
`projection_intervals` 是预扣模型积分区间，不能换算为 CPU 指令或板卡耗时。
连续恢复、累计位置误差界、共享节点/终端预算及末端接续均保留。

原PP19380 ms现场的361障碍和含续段285点缓存由隔离基线取得，活动段130点、进度52。
顺序专项保持44个Grid拒绝、accepted=0，后备工作从132个采用情形、3850次投影、167398个预扣区间、1650次源检查降为零。
基线未记录该帧真实上次采用变化时刻，专项明确提供一周期合成时基以隔离顺序变化；真实时基由另外的Rust/worker回归覆盖。
开放场景44候选仍执行132个前瞻情形并通过，见 `motion-v8-navigation-regressions.json`。

## 固定 2×2 交叉实验

`crates/runner/examples/async_timing_matrix.rs` 固定输入延迟 `[60,80]` / `[40,60]` ms，
分别交叉采用偏移 `[3,7,9]` / `[5,9,11]` ms，PP/LQR 各四场。
其他场景、Q/R、控制频率、10 秒普通停车期限、碰撞及到达门限不变。

```bash
cargo run --release --locked --offline -p xt-stcar-robot-runner --example async_timing_matrix > work/async-timing-matrix.json
```

例程在内存比较真实输出与路线：实际输出按模型时刻对齐；规划动作、路径坐标、路径点数、路线修订号和恢复入口按同一源采集时刻对齐。
路径坐标的首次精确差异不等于路线拓扑改变，报告另列点数和路线修订差异。
每场最多保存 16384 次命令变化、2048 份规划、每份 2048 个路径点；超过容量会显式标记，比较不再声称完整。
只在专用例程启用此记录，默认模拟和真实 worker 不保存这份轨迹。结束统一输出 JSON，未新增比赛逐拍落盘。

`simulate_async_observed` 回调在模拟输出方执行，只能观察最终 poll 与模型状态，不能替换命令或进入 worker/poll 内部。
回调耗时计入主机墙钟，而功能时钟暂停；此矩阵用于功能比较，不用于 CPU 加速或目标截止时间结论。
同一份观察代码可复制到原7d基线：重建原因经可选JSON字段读取，旧版没有该字段，null或空事件列表表示该诊断不可用，不能理解为没有重建。
对比的返回路径包含当前投影位置及剩余参考段，因此坐标/点数变化也可能只反映沿路线前进。

实际 Stop 时长按最终输出状态在相邻输出间的持续时间累计，包括启动和结束制动；它不是物理静止时长。
实际 Stop 段数、导航非预期 Stop、首次观察时的采用拒绝次数以及拒绝期间保持旧 Drive 的输出次数分别记录。
空的首次差异只表示共同观察区间未见差异，并以 `traces_complete=true` 为前提。

最终 **8/8 完成**，曲率变化率采用拒绝与最终证书拒绝均为0，全部保留3000 ms斑马线停稳、300 ms绿灯确认、整车终点及终态速度/曲率归零。
原交叉工况LQR的91.669秒停车超时已改为86.269秒完成；但早输入 `[40,60]` /早采用 `[3,7,9]` 的LQR从54.447秒退化到88.647秒，
路程10.317616→16.515558米。默认PP也从73.863秒变为75.467秒，仍有时序敏感性，不能称为全面性能改善。
同步PP58.800秒/11.508841米、LQR54.300秒/10.249675米保持。
原19380 ms阻断专项44个Grid拒绝/accepted0不变、后备前瞻工作归零；开放44候选仍执行132个采用情形。
完整首次差异、实际Stop和重建原因见[最终矩阵](motion-v8-timing-matrix.json)，范围与测试见[验证汇总](motion-v8-validation.json)。

导航非预期Stop段（同一固定顺序）：PP4/3/2/2，LQR2/1/2/0；实际Stop命令总时长PP4709/4585/4447/4195 ms，
LQR4657/4349/4513/4357 ms。PP恢复尝试4/1/0/0，LQR均0；这些与输出端拒绝全0并不矛盾。

固定输入延迟比较采用偏移时，最早真实输出差异来自启动63/65 ms或43/45 ms；同source动作数值首先在200 ms不同。
100 ms出现的返回路径坐标差异含当前投影位置，不能称为绕行。对晚输入PP，两组首次路线revision差异在source19100 ms，
一侧记录no_accepted_candidate后的重建；LQR晚输入的首次revision差异在14800 ms，一侧为arrival_changed，
包含任务进度时序变化。完整上下文含位姿、phase/waypoint、动作、采用拒绝和路径长度，不把全部差异归因于单一延迟数字。

主机默认异步导航均值/样本最大PP6.395/59.369 ms、LQR4.573/13.166 ms，含非Drive计划；
PP本轮进入恢复，和v7路线及工作量不同，不能由Grid专项工作减少推断整场更快。
同步主机profile分别约+0.76%/+1.47%，各预热1次/测3次，小样本不支持普遍性能结论。
开启计时与无观察回调运行的功能摘要均核对一致（排除计时字段）；目标板时限仍待车到后实测。
