# Rust 模块完善验证记录（2026-09-08）

依据用户提供的整车资料继续采用 Rust 实现 N10 雷达解析、串口传输/采集、底盘物理量标定预览，
并接入现有 YOLO26n 机器人回放。README 已重写为代码结构、逐文件职责、配置和运行入口索引；
agent.md 已更新为一致的交接快照。

本轮未接车、未操作真实串口或电机、未读取视频，也没有安装或更新车端 GLIBC。

## 代码与回归

- N10：58 字节/16 槽、加和校验、大端角度/距离、坏帧重同步、分片首字节时间、固定槽位插值。
- 串口：8N1/流控配置与读回、独占与恢复、统一截止时间、错误锁存；采集默认只输出计划。
- 底盘：显式分段表与零锚点、PWM 包络、倒车策略、拒绝外推；映射失败写完整急停 Stop 并非零退出。
- 日志：同一 IMU/N10 批次只记录一次，多个样本不再重复写整个批次。
- 文件：配置/事件非阻塞打开后验证普通文件，拒绝 FIFO，限制实际读取字节；图片复用已验证句柄。

`cargo fmt --all --check`、全 workspace **91 项常规 Rust 测试**、clippy `-D warnings` 全部通过。

新增 40 项常规测试覆盖协议/标定/串口/采集/文件边界与集成；串口测试仅使用 Mac PTY。

18 项 Python 交付/ELF 回归通过；打包白名单现包含新配置、N10 合成输入和说明。

## 实际运行的回放

N10 + 标定命令：

```bash
target/debug/xt-stcar-robot replay \
  --events examples/robot-n10-replay.jsonl --config config/robot-n10-replay.json \
  --n10-config config/n10-replay.json --chassis-calibration config/chassis-calibration-sim.json \
  --output docs/rust-expansion-n10-replay.jsonl
```

10 个合成输入事件产生 1 包/1 个局部雷达样本、11 条运动记录（3 Drive/8 Stop）。
有效包首字节在 t0 到达，t5 完成；t40 坏校验不刷新时间，t80 触发 `sensor_expired(lidar)`。
最终 Fault/Stop 是测试期望值。每条日志 `physical_output_enabled=false`，PWM 是模拟预览。
完整日志见 [N10 回放](rust-expansion-n10-replay.jsonl)。

由于本轮修改了图像读取和通用输出流程，也重新运行真实原生 ORT 集成：

```bash
.venv-model/bin/python tests/verify_robot_reference.py \
  --runtime-lib toolchains/onnxruntime-macos-arm64-1.29.0/lib/libonnxruntime.1.29.0.dylib \
  --image .venv-model/lib/python3.12/site-packages/ultralytics/assets/bus.jpg \
  --report docs/rust-expansion-robot-reference.json
```

结果：19 输入事件、2 个真实图片帧、同一常驻 Session 各得到 5 个框且检测一致；
20 条运动记录（4 Drive/16 Stop），结束 Disarmed。坏图片非零退出并记录完整急停。
见 [真实模型回放报告](rust-expansion-robot-reference.json)。这是 Mac 推理，不是 RISC-V 或车辆实时性验收。

## GLIBC 2.38 目标构建

`scripts/build-riscv.sh --offline` 通过。Rust 1.97.1、Zig 0.15.2、cargo-zigbuild 0.23.4。
目标 `riscv64gc-unknown-linux-gnu.2.38`；两个 ELF64 LE RISC-V / RVC / LP64D / PIE，加载器
`/lib/ld-linux-riscv64-lp64d.so.1`；最高 GLIBC 符号引用都为 2.34，低于 2.38 基线。
