# Rust 为主的架构与验收边界

维护日期：2026-09-07。实际结果见 [本轮验证记录](验证记录-2026-09-07.md)。

## 运行数据路径

```text
PNG/JPEG -> Rust RGB/letterbox/NCHW -> 常驻 NativeOrtBackend -> 检测张量校验与解码
                                              |                         |
                                    标准 ONNX Runtime C API        原图像素框日志
                                                                        |
IMU / 雷达 / 里程计 JSONL -> Rust 单位/frame/时间校验 <---- VisionSample 摘要
                                         |
                        Controller：启用、急停、deadman、超时、限值
                                         |
                            MotionSink -> RecordingSink / JSONL
```

`xt-stcar` 提供 `self-check`、`preprocess`、`replay`、`infer`。
前面三个命令不执行模型，报告明确区分；`infer` 默认由 Rust 调用原生 ORT。
`xt-stcar-robot replay` 串联事件输入、传感器校验、安全状态机及日志；
事件包含 `vision_frame` 时复用同一 Rust ORT Session，模型错误记录急停并失败退出，正常流结束记录 Stop。

核心数据处理、运行调度和安全逻辑用 Rust。ONNX Runtime 推理引擎是上游 C/C++ 原生库；
Rust 使用 `ort=2.0.0-rc.13` 的 `load-dynamic` 模式，不在交叉构建时链接或下载目标推理库。
模型 SHA、provenance、实际 session metadata、名称、dtype 和形状必须通过校验。
provenance 记录不是数字签名；可信来源与哈希的审计不能被解释为任意外部模型都可信。

原生加载/推理使用 ORT 的协作取消机制，不是对任意失灵 C 库的进程隔离或硬实时保证。
Python 只用于离线导出/校验/数值对照，以及显式 `--backend python-reference` 的辅助参考入口。
参考 worker 每次启动独立进程，采用 f32le/JSON 文件、超时 kill/wait 和有界诊断读取。

## 跨架构边界

Mac ARM64 运行主机测试和参考 ORT 库，两个部署程序交叉生成 RISC-V Linux GNU / LP64D 二进制。
纯 Rust 核心不需要车端 ROS、OpenCV 或 MCU 库。使用真实模型时，目标机必须有经过核实的
RISC-V 标准 ONNX Runtime C 动态库。部署包目前不包含该库；Mac dylib/wheel/虚拟环境不能复制上车。
`python3-spacemit-ort` 的存在或 YOLO11 示例不能证明标准 C API 或 YOLO26n 算子兼容。

## 机器人模块的实际范围

已实现强类型传感器、图像文件输入、模型推理、安全状态机、底盘抽象输出、总调度和日志程序，
并完成无需硬件的整链路回放。尚无真实相机采集、ROS 节点、定位融合或导航算法；现已补 IMU/N10 Rust 协议、串口传输与传感器采集，均未实车验证。
MotionIntent 保持物理速度/曲率抽象；可选显式标定表生成模拟 PWM 预览，不向底盘发送，也不生成虚构轮速反馈。

时间是回放中的单调毫秒，**不会按真实时间等待**。推理耗时不改变模拟事件时间。
因此回放里的超时/急停测试证明状态机规则，不能证明物理停车或真实控制线程的调度时限。
将来接入物理输出，需要独立控制周期、通信超时处理、硬件看门狗和现场停车验证。

## 验收层次

| 已验证层次 | 证明的范围 | 尚不证明 |
|---|---|---|
| Rust/Python 自动测试 | 数据/几何/错误/状态机/回放/构建包规则 | 真实硬件兼容 |
| 26 例 OpenCV 对照 | 固定 PNG 下几何一致，像素差最大 1 级 | 所有图片逐像素或精度等价 |
| ONNX 静态校验 | 锁定版本、metadata、输入输出、opset、无 NMS | 厂商运行库支持 |
| PyTorch 与 ORT 对照 | 一张真实样例的检测数量/类别及数值接近 | 数据集精度、车端帧率 |
| Rust 与 Python ORT 同输入 | 同模型同库的框/置信度完全一致 | 不同车端库必定相同 |
| 真实图像 + 机器人回放 | 常驻 Session 与传感器/控制日志连通，坏帧记录 Stop | 带动力控制或实时视频 |
| 双程序 RISC-V ELF 检查 | 架构、ABI、加载器、动态库及 glibc 引用可追溯 | 目标机已经运行 |
| 两种部署包 | 最小资源与哈希校验，未混入主机环境 | 已上传或已启动 |
