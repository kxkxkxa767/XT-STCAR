# 雷达保底识别与桶位偏移仿真（2026-10-02）

本轮从 `ffdfc244a2d6a2f12663ee74b13688be1504877c` 基线开展。
用户要求检查视觉看不到桶时能否靠雷达绕行，以及桶偏离图中位置后是否仍按任务顺序行驶。
先核对并 fetch 了 main。本轮只修改源码、运行本机仿真；没有连接车端、训练、部署或发电机命令。

## 验证范围

所有场景从发车运行至结束，**两桶视觉检测始终为空**；控制器只接收原始雷达扫描建立桶身份。
桶的真值位置只用于模拟光线投射和独立轨迹裁判，不传给在线任务规划器。
斑马线、灯、停车区域、终点使用模拟专用理想语义观测；位姿也是理想反馈。
这验证雷达独立通路和运动逻辑，不验证 YOLO、相机角度适应或真实定位精度。

标准场地为 7×5 m，第一桶 `(5.5, 2.5)`、第二桶 `(1.5, 2.5)`。
控制器配置保持相同，另外改变模拟场景中的实际桶位：

| 场景 | 第一桶偏移 Δx/Δy（m） | 第二桶偏移 Δx/Δy（m） |
| --- | --- | --- |
| cones_shifted | −0.30 / +0.20 | +0.30 / −0.20 |
| offset_outward | +0.30 / −0.20 | −0.30 / +0.20 |
| offset_both_forward | +0.30 / 0 | +0.30 / 0 |
| offset_both_back | −0.30 / 0 | −0.30 / 0 |
| offset_both_up | 0 / +0.30 | 0 / +0.30 |
| offset_both_down | 0 / −0.30 | 0 / −0.30 |

另跑标准桶位和 cones_shifted 的量程扰动：每束每帧确定性均匀噪声，幅度上限 ±2 mm。
这不是“2 mm 标准差”，不包含丢束、运动畸变、方底座、雷达盲区或位姿噪声。
原有 8 场的 5–8 m × 4–6 m 尺寸变化也保留。
同步每控制拍积分；后台规划还经过输入、计划发布、采用时基、命令有效期与实际执行历史检查。
两组附加延迟测试输入延迟 `[40, 60] ms`、采用延迟 `[5, 9, 11] ms`。
这些是模拟时钟扰动，不能当成车端实时性测量。

## 找到的问题与修改

- **入口接近时丢失最终朝向。** 原先只把远目标裁剪成沿直线的局部点，车辆接近桶的入口导引点时可能已经斜着冲过去。
  雷达模式现在用当前姿态和目标切线构造三次曲线的局部参考；用有界的 32 段弧长表选择参考点，雷达测量先在同身份内平滑。
  它只产生参考点和朝向，实际运动仍须通过 Navigator、KnownFree 和制动/执行检查。
- **可用短圆弧被量化搜索替换成绕远路线。** 对 RollingLocal 的带朝向目标加入原局部范围内的单圆弧连接，
  与无朝向版本共享积分、误差、碰撞检查和预算；原两段弧连接仍优先，Fixed 行为保留。
- **出口在车还带着曲率时直接跳到延伸直线。** 雷达模式先在半圈出口切线处停稳、满足原位置和朝向条件，再沿出口清出桶区。
  实际半圈进度、外侧经过、出口投影和已处理身份条件均保留。没有把“目标点到达”直接写成桶任务完成。
- **绕行半径只看近侧半段。** 已观察到的灯前禁止区域现在参与整个半圈半径筛选，按车体外接半径、净空和弧弦误差留边界。
  这只是提前排除不合适的候选半径，不会把尚未观察的空间标为可通行。
- **雷达几何小幅抖动触发频繁重规划。** 唯一关联且连续观测的同一身份进行位置平滑；误差增加平滑中心与当前测量中心的距离，
  不通过平滑声称更高精度。观测间隔过长重新确认，时间戳仍来自真实扫描；YOLO 丢检不让雷达身份过期。

未增加速度、转向上限、位置/朝向容差、净空、搜索预算或普通停车 10 秒上限。
第一桶逆时针、第二桶顺时针；已处理桶排除、task_revision 和下一元素语义新鲜度继续生效。

## 最终结果

不能只凭“通过”忽略性能与小扰动敏感性。

五个失败逐项保留：

- small_5x4 同步、异步：停在第一桶出口前，约 0.19 rad 的朝向误差尚未消除，普通停车超时，均 0/2。
- tall_5x6 同步：两桶已通过，灯前接近停滞；异步：第一桶过程中绕远，未完成有效半圈，0/2。
- offset_both_back 同步：两桶通过，但入口接近绕远消耗时间，在终点前用尽原 180 s 场景时限；未延长时限凑通过。

本轮先复现了基线 cones_shifted 同步/异步各只完成第一桶的失败。最终版本这两项均完成整场。
32 项最终实际速度/曲率均为零，已执行轨迹最小桶净空约 0.253 m；这些只针对所述理想模拟模型。
完整工作区 **618 项通过、0 失败、3 项历史忽略**；fmt 与全目标 clippy（警告即错误）通过。

成功由独立实际轨迹裁判判断：两桶半圈、外侧、入/出口方向和顺序都通过；再要求整场完成、
无故障、斑马线停足 3 s、绿灯新帧持续至少 300 ms、最终实际速度和曲率为零。
`lidar_matrix` 会先输出所有 JSON 结果，只要有一项未通过就以非零状态退出。
安全停住、任务自报 processed=2 或 order_valid 单独为真，都不能替代通过。
