# y58 第二桶转向连续修正与近期速度锚定

基线为实车 y57／164（`7b2c0dc`），该轮扣红灯 21.382 s。用户看到驶向第二桶时短暂左偏，要求分析后直接修复。本轮候选编号 y58／165。

## 转向

y57 的第一桶交接帧保留旧左舵1710，下一帧才开始回中，航向曾到约220.8°。现在交接当帧就用现有过渡通道／回程轴转向目标，经原来的中位交接及舵机渐变执行。只计算转向，不重复第二桶观测，也不提前执行过渡段油门逻辑。

第二桶接近直线的旧前瞻只在预测舵角跨过中位后生效，同方向的提前回舵被忽略。现在该局部控制用当前与响应窗口末端追踪曲率的梯形平均，提前逐步减小右舵；预测角速度改用本拍标定 IMU。y57 第137帧雷达角速度仍为−1.210 rad/s，IMU已经回到−0.091 rad/s，继续按旧雷达角速度外推会放大反打。

新逻辑仅作用于比赛模式的第二桶 `approach_line`。共同 `overshoot_guard`、灯区预测、第一桶圆弧、半径选择、y50早切点规则及y53随速度变化的前视距离保留。目标速度也保留。

## 负载估计的测速

y57错误地跨第一桶继续使用从斑马线静止点开始的长积分速度，导致学习在104帧后冻结。新增独立 `race_surface_speed`：

- 复用现有五帧雷达轴向速度及其窗口首末接收时刻。用窗口中点近似坡度的代表时刻，将对应航向投影换成车体前向速度，再加这一小段至当前的IMU速度增量。
- 初段轴向为起步方向，回程轴向为其反向；不对投影余弦取绝对值，近横向时不放大除法。
- 原有低转速判据作用于整个测量窗；转弯丢弃旧锚点，暂缺雷达只按既有0.30 s时效短暂传播。无可用速度时仅退回额外补偿，原阶段驾驶继续工作。
- 固定8条小数组，不增加线程。原始相邻IMU积分差仍用于计算加速度，不把雷达重锚产生的速度跳变算成物理加速度。

新速度只供负载学习、补偿和补偿余推预算，不替换原第一桶／过渡段的基础档位或速度决策。新增 `surface_speed` 日志，保留锚点时刻、投影和失效原因。

Rust直接引用生产模块，用y57真实保存扫描和原始IMU核对：第141帧从旧长积分0.149变为约1.892 m/s；145帧从0.120变为约1.963 m/s。141帧使用真实已保存的137–141窗口首末时刻。121帧仍处大转弯，新模块不给无依据的速度；149帧转动增大后也丢弃旧锚。

日志约6 Hz，车端控制扫描为10 Hz，不能重建全部未存帧。在相同稀疏输入上，旧实现104帧后新增学习为0；只采用真实已存窗口首末时刻的子集恢复1次学习，显式采用0.4 s窗口近似时恢复3次。额外负载及补偿仍为0，符合本轮瓷砖条件。不能把这些稀疏输入的计数直接与实车完整25次相比。
