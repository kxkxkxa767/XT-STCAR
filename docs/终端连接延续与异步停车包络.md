# 终端连接延续与异步停车包络

本轮基于 `f83898a` 和用户提供的 `XT-STCAR_f83898a_review_reproduction.zip` 修正。
分享页在网络恢复后仍返回“Can't load shared conversation”，未读到完整第五份意见；已核实的工作依据是本地复现包，不能称为已逐条处理分享正文。

## 原问题与证据

[修正前记录](motion-v5-before.json)保留 ZIP 哈希、来源和对比口径。
ZIP 只有几何 Python 探针与计算结果，没有 Rust 补丁、原始点云或新的整场验收。
其 35:65 双段曲线给出了有价值的数值初值，但没有经过实际障碍、网格、车体、制动、速度/曲率及比赛边界检查。
六种段比各自最多八次迭代，也不能称为总共只需八次迭代。

在隔离的原提交中只加三条内存诊断，重放原 LQR 合成比赛，得到
[42.1/42.2/42.3 秒输入](motion-v5-original-input-window.json)，每帧包含360个激光距离和同源位姿投影出的360个世界障碍点。
整场时间、路程和这三帧导航诊断与已提交 v4 数据完全一致。此文件是模拟输入证据，车未连接。

42.2秒，44个候选通过原有运动/碰撞硬检查，却均未被下一状态的等长双段短连接求解器认证。
当前状态存在短连接，下一状态的固定八次迭代失败不能推出物理不可达。
下一拍新路线长4.439964米，旧路线**剩余**0.916363米，相差3.523601米；不能拿两条完整路线长度相减。
原 LQR 灯前阶段平均速度约0.17865米/秒，PP约0.17166米/秒，较长路程是耗时差的重要来源。

## Rust模块与计算边界

- `crates/robot-core/src/navigation/terminal.rs`：单/双段渐变曲率连接、剩余段数值初值、共享求解额度和诊断。
- `crates/robot-core/src/navigation.rs`：正常候选硬检查、终端接续选择、路径和目标状态。
- `crates/runner/src/control_execution.rs`：已采用命令历史、时间投影及源车体坐标中的停车包络。
- `crates/runner/src/phase_statistics.rs`：每阶段固定计数和每拍最大值，保留路线/Stop统计。
- `crates/runner/examples/motion_profile.rs`：显式运行的主机整场墙钟测量。

短连接的缓存仅是数值初值。每次都用当前规划状态、当前障碍网格和比赛半平面重新积分/求解/认证；
后台计划即使未被采用，也不能凭缓存跳过这些检查。
共享额度覆盖同一次导航内的端点、lattice末端和候选连接调用；全局搜索原有节点额度另行保留。
普通冷候选有解时沿用原选择；只有全未获认证时，恢复轮按接近当前认证首段曲率的顺序，
采用第一个通过原运动/碰撞门和剩余完整连接检查的动作。恢复轮不重新计算rollout，也不枚举额外速度/曲率。
单次求解最多八次迭代，整次导航最多256次域内求解、1024次迭代、65536份预扣样本；不枚举六种比例再把各自预算当作总预算。
共享额度耗尽时结束已不可能产生结果的lattice搜索；已经完整认证的候选仍可保留。
`solver_iteration_exhaustions` 单独记录八轮用尽，`budget_exhausted` 记录全局额度不足。
候选 `terminal_budget` 表示在共享预算限制下未继续认证，`terminal_unreachable` 可包含域/网格/数值求解失败，两者都不宣称数学无解。
`primitive_samples` 是在每条 primitive 执行前预扣的采样额度，遇到障碍提前退出时实际执行量可能更小，不能将它写成实际CPU操作数。
预算用尽和有限求解族未收敛均只表示此次没有取得所需认证，不是不可达的数学证明。

## 整场选择与结果

第一种扩大所有候选连接族的尝试使原镜像S形到达回归失败，已撤销。
第二种只在冷候选全部失败时恢复、再按原恒曲率评分选最优的尝试，消除了42.2秒Stop，
却在44.8秒走上更长路线，使LQR变成79.7秒/15.057722米，也已撤销。
最终按认证首段优先选首个可行恢复动作，完整结果如下；[实验记录](motion-v5-terminal-experiments.json)保留了退化方案。

| 指标 | v4 PP → v5 PP | v4 LQR → v5 LQR |
| --- | --- | --- |
| 完成时间 | 58.8 → 58.8秒 | 70.6 → 54.3秒 |
| 实际模拟路程 | 11.508841 → 11.508841米 | 13.440314 → 10.249675米 |
| 灯前阶段 | 27.8 → 27.8秒 | 42.4 → 26.2秒 |
| 灯前路程 | 4.772231 → 4.772231米 | 7.574950 → 4.390629米 |
| 灯前路线生成数 | 9 → 9 | 8 → 5 |
| 全场非预期Stop tick | 2 → 2 | 1 → 0 |
| 最小锥桶间隙 | .242509 → .242509米 | .273528 → .273528米 |

两者完成、终速0，斑马线停稳3000ms、绿灯确认300ms，数据见[正式完整比赛](motion-v5-competition-comparison.json)。
这轮没有通过修改Q/R、放松比赛规则或碰撞门限取得这些结果。PP仍是默认，单场合成数据不能证明LQR普遍更优。

## 异步停车空间

v4证书以最高配置速度和完整原期限生成全向圆盘，默认半径约0.47554米，因此无法通过0.9米宽的合成直道。
0.9米是验证用场景，官方赛道宽度没有据此确认。同步导航本身可能已给出Drive，异步采用阶段却会因圆盘越墙退回Stop。

新证书用源车体坐标中的矩形包住到原期限、额外一拍以及完整刹停期间的所有车身位置。
速度上界V涵盖原始有效测量、源时刻至规划时刻所有**实际采用**目标、投影速度、当前保持目标与候选目标；
曲率绝对值上界K同样保留历史及执行估计。最新低速或Stop不能抹掉过去的高速/大曲率。
位移上界不依赖导航加速度，避免把比导航加速更快的模拟车辆遗漏在外。

令T为源位姿捕获到原lease结束再加一拍的时间，b为制动减速度下界：

- 总弧长 `S = V*T + V²/(2*b)`。
- 朝向变化绝对值不超过 `K*S`；横向位移不超过 `min(S, K*S²/2)`。
- R为后轴到最远车角的距离，车角旋转位移不超过 `min(R*K*S, 2*R)`。
- 当 `K*S >= π/2` 时，还为车体后方向增加S，包含大角度转回后的向后运动。

加入原车体尺寸、clearance与浮点误差垫量后，检查旋转到世界系的四角是否位于地图和灯前半平面内。
障碍在同一源车体系计算圆盘到矩形的最近距离，保留激光外参、激光点半径和锥桶半径，相切也拒绝。
原采用窗口、命令序号、原源期限、正常加减速/曲率slew和侧向过渡检查继续生效；poll不进行全局规划。
同步导航的原紧急停车硬检查没有因此缩小。

该包络基于静态障碍、前进运动、无侧滑/超调和足够制动能力的模型。它仍可能保守拒绝转弯或狭小空间，
不替代真实执行反馈、传感器共同时间轴、扫描去畸变、动态障碍处理或实测制动距离。
完整异步比赛和目标板最坏耗时尚未验证。

## 验证入口

```bash
cargo run --release --locked --offline -p xt-stcar-robot-runner --example motion_comparison
cargo run --release --locked --offline -p xt-stcar-robot-runner --example motion_profile -- 3
cargo test --locked --offline -p xt-stcar-robot-core --test terminal_approach
cargo test --locked --offline -p xt-stcar-robot-runner --test async_autonomy
cargo test --locked --offline -p xt-stcar-robot-runner --test control_runtime
scripts/build-riscv.sh --offline
```

`motion_profile`每种跟踪器预热一次再测3次；可显式指定1至20次。测量完整simulate调用，含合成RGB/激光、控制、车辆模型和sink遥测，
不计报告序列化。每次记录完成状态/错误、模拟时间与实测墙钟，报告总值/平均/最大值。
主机墙钟包含调度噪声；模拟秒数、主机墙钟和板卡实时期限是不同指标。
默认PP、LQR实验；比赛容差、停稳/绿灯时间及LQR的Q/R保持。统计在有界内存累计，结束输出，不新增默认逐拍落盘。

## 本轮计算与交付记录

[主机测量](motion-v5-host-profile.json)使用同一示例文件、同一配置、顺序执行的release二进制。
原提交用于取三帧数据的模拟器插桩在测量前已恢复原字节，并核对全部80份原源码/清单哈希。
每种跟踪器预热1次、测3次，各样本完成状态和模拟时间/路程均与对应整场报告一致。

| 完整simulate墙钟 | 原提交平均 / 最大 | 本轮平均 / 最大 |
| --- | --- | --- |
| PP | 1.621006 / 1.633061秒 | 1.613711 / 1.614437秒 |
| LQR | 1.921360 / 1.926261秒 | 1.496230 / 1.507993秒 |

PP变化约−0.45%，不足以证明一般性能提升；LQR总计算约少22.13%，包含路线变短和控制拍数减少的影响。
这不是同一导航调用的纯CPU A/B。正式整场最大终端求解/迭代/预扣采样分别为PP 47/305/28064、LQR 58/398/52748，均未耗尽共享额度。

[异步验证](motion-v5-async-validation.json)的独占顺序复跑：360/2048点各2000次证书调用，平均8.862/19.234微秒，
采样最大59.791/56.875微秒；真实默认Worker的23次提交到结果可见平均2.626毫秒、最大3.790毫秒。
后一项包含规划和线程调度，采用冻结合成时钟；所有数据均只反映本机样本，不能宣称目标板100ms截止时间已满足。
