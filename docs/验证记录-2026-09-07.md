## 实现结果

四个 Rust crate 形成两个程序：`xt-stcar` 为视觉 CLI / 原生 ORT 后端，
`xt-stcar-robot` 为传感器、图像事件、安全状态机及日志总调度。
默认推理直接调用标准 ONNX Runtime C API；Python 仅离线工具和显式参考后端。
强类型 IMU/雷达/里程计/视觉、启用/急停/超时/限值策略、MotionSink/RecordingSink、
JSONL 输入与原子日志输出均已实现，不只是空接口。
具体硬件驱动、ROS、定位融合、路径规划/避障仍需后续资料与任务，不列入已完成范围。

## 部署边界

core 包含两 Rust 程序、配置、机器人样例、使用说明与校验记录；with-model 额外含 ONNX、
provenance 与许可。上传脚本默认 dry-run，本轮不执行真实上传。
最终 core 包 1,349,792 字节/15 文件、with-model 包 9,994,556 字节/19 文件；
独立外层字节 SHA256、全部载荷 manifest 与 dry-run 均通过。
详见 [归档校验证据](delivery-validation-2026-09-07.json) 与 [部署说明](部署包使用说明.md)。
归档校验工具曾发现并修复变量遮蔽导致返回外层 SHA/大小错误，已补独立回归；载荷不受影响，
最终旁 SHA256 已修正并用外部 shasum 以及独立 Python hashlib 再核对。

**尚无经核实的 RISC-V ORT C 动态库。** Mac 的 dylib、wheel、虚拟环境不进包。
车端真实推理、厂商接口、相机/传感器/底盘/ROS 与标定仍待后续实机核实。
当前纯 Rust 自检、预处理、张量回放和无模型机器人回放不依赖推理库。
