# y59 灯区出弯测速与可视停点刹车

用户在y58第二轮现场确认：灯区停车过于靠前，停车后看不到信号灯；并明确授权预计相机会丢灯时使用1300强制停车。本轮从实车y58／165修正，候选y59／166。

## 真实证据

y58首轮光电传感器异常（用户确认），相机红灯、绿灯都为0，不作有效整圈成绩。第二轮光电恢复后红灯4次检出、绿灯0次，车头最终距门架仅0.0629 m，原目标为0.55 m。第61张照片红灯已被上边沿裁掉，第71张停车照片看不到灯头。程序依据首次见红后10.5秒且当前没有新鲜红灯的既有兜底放行。

按历史保存反馈口径，第二轮起步至终点30.653 s，扣等灯9.584 s为21.069 s；其起点后距0.54 m，y57约0.35 m，不能把圈时变化全部归因于控制修改。第二桶转向改进在两轮中均未再出现原1605的大反打，桶间均约3.495 s。负载学习恢复，第二轮过第一桶后新增6次；209个保存快照补偿均为0，因此灯区冲近并非额外加油所致。

灯区第161–163帧，门架直接测距的区间闭合速度约1.664 m/s，但第163帧控制器“当前速度”只有1.099 m/s。旧速度为历史轴向坡度加IMU前向增量，漏算车头摆正时投影余弦增大。第166帧参考缺测后又沿用旧轴向速度1.276 m/s继续1550。第168帧已收油，预测停车位置却已到门架后0.153 m。保存的168–192帧全部为1500，没有反复补推；门架目标也没有在末尾突跳近半米。

## 修正

`RaceLight`保留自己的小窗口，逐原有差分区间计算航向余弦和IMU积分的加权积分，由实际轴向位移反推当前车体速度，再投影到本拍灯区方向。平均投影不够可观测的区间不反演；这只影响测量，不限制驾驶速度。短暂缺参考时用最近车体锚点加IMU增量，限于原有0.30 s数据时效；保存的备用速度也改成当前修正值。下拍位置预算加入车头摆正带来的轴向加速度项。

新 `race_light_brake` 独立管理灯区一次1300。滑行预计会越过0.55 m可视停点，并且再等一拍将用尽到该停点的强刹距离时开始，避免远处立即刹停在光电线外。强刹模型采用这台车已有的约0.95 m/s²及0.10 s起效参数；开始后连续1300，低速停稳后回1500。是否登记红灯停车等待仍由红灯识别决定。

新红灯帧不会在刹车中插入1500，暂缺速度也不反复点刹。中断或质量暂停会终止这一次刹车，并清掉缓存的1300，恢复时不会重复发送。输出白名单、ACK采纳、中位转向证明、暂停中的延迟ACK路径同步接入，只针对比赛灯区。绿灯后1600起步与终点刹车状态保持独立。

两桶转向、基础速度档位、斑马线及终点控制未改。没有新增阶段超时、限速或车端线程。灯区雷达窗口仍最多7项。

## 验证范围

第163帧仅修正中点投影时可从1.099变为约1.418 m/s。用真实保存参考和原始IMU输入生产模块的稀疏核对，第163/164帧分别约1.576/1.598 m/s。去掉164帧的参考时，当前速度仍可由短锚传播；超过0.30 s后失效。保存频率约6 Hz，生产扫描10 Hz，缺失帧没有补造；尤其第165帧未保存，无法精确重现当时的历史重置。稀疏核对在168帧曾得到2.118 m/s，不能把它当作真实当前速度或完整重放。以实车下一轮的新速度、收油、刹车和停点日志为准。
