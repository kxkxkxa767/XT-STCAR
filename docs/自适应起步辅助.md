# 根据实际运动反馈逐步起步

2026-09-17。用户要求适应操场路面：检测车辆是否移动，未移动时按步进增加PWM。已实现Rust状态机、扫描里程计结果适配接口、离线回放命令与故障测试。**尚未启用实车自动加油门**；现有主工程没有已验收的物理执行闭环，刚才实车所用的独立诊断脚本也未改成自动递增。

起步还受静摩擦、负载、电池和电调死区/状态影响，不把未知动摩擦系数换算成固定PWM。1550首轮仅前倾回位、复测又前进，正说明固定起步数值不能直接用于比赛。

## 实现和状态

- `crates/robot-core/src/startup_assist.rs`：无硬件I/O的确定性起步辅助。
- `StartupAssist::update_with_localization`：直接接收已有 `ScanOdometry` / `LaserPosePipeline` 的 `LocalizationUpdate`；定位预热应在起步前完成，运行中拒绝或重新初始化立即停车锁存。另一 `update` 接口供录制反馈回放；`None`只是暂无新帧，不代表车辆静止。
- `crates/runner/src/startup_replay.rs` 与CLI `startup-replay`：生成PWM建议及原因记录，不打开执行器。
- `config/startup-assist-sim.json`、`examples/startup-assist-sim.jsonl`：全部是合成演示数据，不能当作操场参数。

未配置enabled时默认关闭；现有比赛配置和回放路径不自动启用。演示文件显式enabled=true且simulation_only=true。流程为：

1. 上游必须已有正向Drive、短期有效的执行许可和合格定位。先保持中性，连续确认静止基线；不能一收到前进目标就从高PWM启动。
2. 从配置起始PWM与名义PWM的较大值开始。每次加档必须同时满足本档等待时间、持续静止窗口、足够数量的新定位帧；每次只加一步，不补发错过时刻的多个阶跃。
3. 超出静止容差的微动、短暂前移后回位或运动速度迹象，会禁止本轮继续加档。连续多帧显示达到正向位移和速度门槛才确认起步；未能确认则受总时限约束，不能永远保持助推。
4. 确认起步后立即停止递增、输出Handoff，交还正常速度控制。不能把最后的起步PWM当作巡航PWM一直发送。之后再次停滞会停车锁存，不在同一轮反复加油冲障碍。
5. 上游Stop或零速度请求立即输出中性。传感器无效/过期、定位坐标系或epoch变化、反馈/控制时间异常、许可失效/缩小、速度超限、启动段位移超限、倒退/明显横移/偏转、PWM上限及总超时均停车锁存。Stop不能自动清除故障；显式重新检查并复位/解锁后才能新建起步流程。

静止判定同时看连续位姿变化及实际速度，使用定位时间戳；旧帧重复发送不会增加静止/运动计数。单帧抖动不会直接判为可靠起步。质量分数来自已有扫描匹配启发式，并不是测量误差的概率保证；阈值仍需路面实测。

## 参数与执行许可

主要参数为 `start_motor_us`、`step_us`、`step_wait_ms`、`max_motor_us`、`max_attempt_ms`；另设静止窗口/样本数、起步位移和速度阈值、最大起步位移、横移/航向限制、定位质量及新鲜度限制。

演示采用每1000ms最多加2µs、总尝试4000ms、PWM1510–1514，**仅用于证明逐步递增和退出逻辑，不是实车推荐值**。当前没有把1550或1552固化为起步参数，没有把1秒脉冲后的净位移当稳态速度。

`StartupPermit` 由上游每次提供签发时间、有效期、允许的最大PWM和最大速度。PWM上限不能只由“名义速度已获准”推导；必须验证助推对应的真实加速度、响应与停车包络，且最终执行门仍可拒绝任何Preview建议。这里的许可只是调用接口契约，**不自动生成安全证书**。比赛现有世界模型/负边界/停车门尚未接线到实测PWM包络，不允许构造一个常量true或远期有效许可绕过它们。

实现只支持PWM随正向驱动力增大、转向保持当前合法命令的起步路径。倒车不启用；起步期间目标速度、曲率或名义PWM发生变化会停车重启流程，避免把旧助推沿用到新请求。进入Handoff后允许正常速度控制改变目标。

## 回放

在工程根目录：

```bash
cargo run --locked --offline --bin xt-stcar-robot -- startup-replay \
  --config config/startup-assist-sim.json \
  --events examples/startup-assist-sim.jsonl
```

每条输出都标记physical_output_enabled=false。示例先确认静止，预览1510，再预览1512，随后检测到合成前移并Handoff，最后Stop。末尾必须显式Stop；输入完整解析和配置校验后才生成输出，拒绝覆盖输入路径。发生起步故障会保留锁存Stop记录并返回非零，不能把命令退出0误当实际起步。

## 实车启用前仍缺什么

需在比赛相近路面建立低速起步重复性、阶跃响应、滑行/停车距离与PWM安全上限，完成时间对齐、雷达外参和在线定位质量验证，再接入实时最终执行检查、串口看门狗和独立停机路径。现有连续雷达测试是离线分析，不是实时自动刹停；主控/通信故障也不能仅由本模块保证停车。上限、步进和等待时间不能靠一次室内试跑确定。
