# XT-STCAR RISC-V 部署包

本包面向 `riscv64gc-unknown-linux-gnu`，使用 Rust 1.97.1、Zig 0.15.2、cargo-zigbuild 0.23.4，
交叉链接目标固定为 `riscv64gc-unknown-linux-gnu.2.38`，ELF 允许的最高 GLIBC 引用为 2.38。
这不包含车端系统 libc 安装；程序实际需要的最高版本见 ELF 报告的 `maximum_glibc`。
视觉程序 `bin/xt-stcar` 与模块运行程序 `bin/xt-stcar-robot` 的 ELF 检查结果
分别见 `elf.json`、`robot-elf.json`；两程序 SHA256 与全部 Rust 源码哈希证据见 `build.json`。
这些是主机侧构建证据，车端执行、YOLO26n 算子兼容性、检测精度与延迟仍需实测。
当前运动控制扩展的主机测试与实验结论见 `docs/motion-control-validation.json` 和
`docs/运动控制设计与对比.md`；LQR尚未通过完整比赛模拟，默认使用Pure Pursuit。

## 在 Mac 构建与打包

在工程根目录执行，已有锁文件与工具链是前提：

```bash
scripts/build-riscv.sh --offline
scripts/package.sh
# 只有显式指定才携带模型；指定 Python 必须已安装模型静态校验所需的 onnx。
scripts/package.sh --model models/yolo26n.onnx --python .venv-model/bin/python
```

省略 `--offline` 允许 Cargo 下载锁定依赖。构建脚本执行 fmt、主机测试、clippy、两个可执行文件的
交叉链接和独立 ELF 检查。打包前重新检查两个 ELF、二进制/源码哈希、完整 Rust 源文件集合并按需校验模型。
包写入 `dist/`，不会覆盖已有包。
`manifest.json` 与 `SHA256SUMS` 记录全部载荷；旁边的 `.sha256` 校验压缩包本身。
校验哈希用于检测传输/文件变化，不是数字签名。

包中包含两个 Rust 目标程序、视觉/机器人配置、机器人回放样例与模块说明、可选参考用的
Python worker/validator、只读检查脚本、本说明及证据；
默认不含模型。带模型时必须在模型旁有 SHA256 匹配的 `.provenance.json`，包内附原始导出来源记录、
静态校验结果和 Ultralytics 许可；来源记录中的模型哈希和元数据必须与当前 ONNX 校验结果一致。
不含虚拟环境、Mac wheel/dylib、编译器、缓存、完整源码或厂商资料。

默认推理走 **Rust 原生 ONNX Runtime C API 动态库**，运行时不会启动 Python。
本包尚不提供 RISC-V ONNX Runtime C 动态库；真实推理需要另外取得并核实适用于车端的标准 C API 库。
官方 SpacemiT 2.0.6 候选库的 C 导出和 API 24 头文件已静态核验；
实际 `GetApi(22)`、模型推理和厂商 EP 尚未在目标平台运行验证。
该候选库需要 GLIBC 2.38，EP 还需要 GLIBCXX 3.4.32 / CXXABI 1.3.15；仅升级 GLIBC 不代表全部依赖满足。没有推理库时，离线预处理、检测张量回放、
合成自检及机器人无模型回放仍可纯 Rust 运行。
Python 只用于离线导出/校验，或明确选择 `--backend python-reference` 的参考后端；
参考环境需独立准备，不将 Mac 虚拟环境复制到车上。

## 上传（本阶段不自动执行）

先取得新车 IP、非 root 账号和 SSH 主机密钥，并在常规 SSH 流程核实密钥。
以下 IP 和账号是文档占位，必须替换成新车实际信息。独立目录必须是
`/home/账号/xt-stcar/releases/新名称`，仅允许字母、数字、下划线和连字符作为新名称。

```bash
scripts/upload.sh --archive dist/实际包名.tar.gz \
  --host 192.0.2.10 --user vehicle \
  --remote-dir /home/vehicle/xt-stcar/releases/first-check
```

默认 dry-run 仅验证参数和本地包，不执行 SSH/SCP。需要上传时在同一命令末尾增加 `--execute`。
脚本使用已核实的主机密钥与非交互认证，在新目录创建失败时停止；已存在的 release 不会覆盖。
上传的文件名为 `bundle.tar.gz`，随后核对远端 SHA256。上传不会解压、启动程序、安装依赖、
修改厂商服务或操作电机；中途失败可能留下不完整的新 release，需检查后选另一个新名称重试。

## 车端手工检查与运行

先在新 release 目录检查归档列表，再解压并校验：

```bash
tar -tzf bundle.tar.gz
tar -xzf bundle.tar.gz
sha256sum -c SHA256SUMS
bash scripts/check-vehicle.sh
bin/xt-stcar --help
bin/xt-stcar self-check --config config/yolo26n.json
bin/xt-stcar-robot --help
```

只读脚本记录系统、加载器、Python 包是否存在、USB 设备和已有服务，缺失命令只记录结果。
脚本不打开相机/串口、不发布 ROS 消息、不启动服务。`self-check` 为合成数据自检，不执行真实推理。
上传脚本不做这些手工运行步骤。请先核对实际 GLIBC、RISC-V ISA/ABI 与 ELF `needed` 库。

车端已取得经过验证的 RISC-V 标准 ONNX Runtime C 动态库后，可按以下格式运行离线图片推理，
其中库路径必须替换为实际已核实的路径：

```bash
bin/xt-stcar infer --image IMAGE.png --model models/yolo26n.onnx \
  --runtime-lib /实际路径/libonnxruntime.so
```

程序默认读取相邻的 `models/yolo26n.provenance.json`，先核对模型哈希、契约及会话元数据。
机器人运行模块和 `config/robot-sim.json` / `examples/robot-sim.jsonl` 的用法见 [机器人模块](机器人模块.md)。

本轮未接车，也未验证真实 ROS、相机、底盘、IMU 或雷达驱动；回放与诊断不代表硬件已接通。

## 厂商协议离线验证

`xt-stcar-robot` 新增 `chassis-preview` 与 `imu_bytes` 回放，附 IMU 合成配置和样例；见 [厂商协议 Rust 适配](厂商协议Rust适配.md)。均不打开串口或产生物理输出。

## Rust 雷达与串口模块（2026-09-08）

包内增加 N10 合成回放、底盘物理单位标定预览配置与传感器串口采集计划配置。
`replay --n10-config` 和 `replay --chassis-calibration` 都只写本地日志。
`serial-capture --config ... --output ...` 默认生成计划；只有显式 `--execute` 打开传感器端口。
详见 [N10 协议](N10协议依据.md)、[标定映射](底盘标定映射.md) 和 [串口采集](Rust串口采集.md)。
本轮仅使用 Mac PTY 测试串口，未执行真实设备采集，也没有底盘发送入口。

## Rust 比赛模拟闭环

包内新增任务/视觉/导航的合成场景、控制器、道路识别、全圈扫描和激光里程计配置，
并附 [Rust 比赛自主闭环](Rust比赛自主闭环.md) 与根目录 `Mac与车端命令手册.txt`。
这些配置均需实物测量，当前不接受直接作为已标定车辆配置。

```bash
bin/xt-stcar-robot autonomy-sim --config config/competition-sim.json
```

该命令不需要模型或设备，生成 RGB/雷达反馈并计算运动意图，最终输出模拟摘要。
它不打开串口，不输出电机指令。默认在内存处理，只显式指定 `--output` 才在结束后保存日志。
正常运行与比赛优先于 eMMC 节写；不会为日志额度降低传感器频率或触发控制故障。
