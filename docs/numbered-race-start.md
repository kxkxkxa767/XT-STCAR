# 比赛启动命令

在车上的 Bash 终端使用 `start_程序号_最大等灯秒数`。程序 1 取自当天实跑的 y114／219，程序 2 取自 y115／220 建图版。两套实际执行程序均使用 N10P、460800 baud 和现有 N10P 安装标定。默认相机模型为现场第 21 轮使用的 `mix`。

| 命令 | 作用 |
| --- | --- |
| `start_1_7` | 运行现场版，本轮灯区最长等待 7 秒 |
| `start_2_12` | 运行建图版，本轮灯区最长等待 12 秒 |
| `start_2_7 --profile light` | 运行建图版，选用晴天模型 |
| `start_1_7 --show` | 回读实际选中的版本、模型、可执行文件和秒数 |
| `start_2_12 --check-only` | 运行相机、雷达和 ROS 2 启动检查，电机保持锁定 |
| `start_1_7 --status`、`start_1_7 --stop` | 查看或停止当前共享的比赛服务 |

识别到有效绿灯后按原有两帧规则放行。如果先识别到红灯，从第一次红灯开始计时。停车后最多等待命令指定的秒数，停车后迟到的红灯不会重新延长等待。秒数可以是 0 或非负小数，仅对本轮生效。

编号入口把选定的程序和秒数带过后台 systemd 单元，直到实际控制进程。同一个可执行文件派生本轮 ROS 2 控制和雷达进程。已有三个天气配置继续可用，可通过同一入口的 `--profile dark`、`--profile light` 或 `--profile mix` 选择。

## 安装

程序 1 的源标签为 `race-program1-y114-wait-20261121`，以 `41337e1` 为直接父提交。程序 2 在主分支上继续维护。两套分别使用 ROS 2 构建参数交叉编译，并用 `scripts/inspect_elf.py` 的 `ros2-humble` 配置检查 ELF。主机工具 `scripts/install-numbered-programs.py` 接收两个已编译的 ELF 和各自源提交，安装到车上的版本目录，以单个符号链接切换编号入口。

车上 Bash 配置负责识别命令名，现有模型和桥由独立的两份启动配置引用。已开的终端可直接通过 PATH 使用 0–60 的整数秒组合，重新加载 `~/.bashrc` 或新开终端支持其余非负秒数。桌面 `Rust` 文件夹单独保存 N10 交付源码。
