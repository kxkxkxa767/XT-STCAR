# 视觉驾驶台部署交接（2026-09-22）

GitHub源码同步和车端部署是两件事。`c86cd80` 已包含新版源码，但当时没有同步到车端。
可下载的完整补充部署包位于 [GitHub Release：vision-console-20260922](https://github.com/kxkxkxa767/XT-STCAR/releases/tag/vision-console-20260922)，编译产物作为附件发布，不提交 Git 源码历史。

## 包里有什么

- `console/`：RISC-V `vision-shadow`、`vehicle-bridge`，以及完整新版 `server.py / vision_shadow.py / app.js / index.html / style.css`。
- `service/`：`run-service.py / start-console.py` 和供核对的 systemd 用户服务单元。
- `config/`：单蓝桶、四类、官方80类模型配置，以及默认禁用的 `vision.json` 示例和模拟地面配置。
- `scripts/`：导出、校验及只读部署检查工具。
- `docs/`：模型接口、部署方法、运行库历史安装路径和验证记录。
- `MANIFEST.json / SHA256SUMS`：文件清单、二进制与源码提交对应关系、完整性校验。

保留车端访问码和录像，不把它们放进公开附件。模型权重和 ORT 库不随这个包重复分发。
`vision-shadow` 的核心代码来自 `c86cd80`；后续交接提交只补模板、检查脚本和文档，不改变导航或遥控算法。

## 队友还需要准备的文件

| 项目 | 要求 |
| --- | --- |
| 蓝锥桶模型 | YOLO26n Detect，静态FP32、输入 `[1,3,320,320]`、one-to-one输出 `[1,300,6]` |
| 模型校验记录 | 与 ONNX 同名 `.provenance.json`，由工程导出脚本生成，不能手写 `validated=true` 代替检查 |
| 模型配置 | 真实类别名称、顺序、数量必须一致；单蓝桶可从 `yolo26-blue1.example.json` 改起 |
| 运行库 | 复用车端已验证的 RISC-V ORT；不能使用Mac dylib、Windows DLL或系统旧版ORT |
| Python依赖 | 车端 `python3` 能导入 `cv2`、`numpy`；无需把训练用PyTorch安装到小车 |

若模型类别实际叫 `blue_cone`，示例的 `class_names` 应改为 `["blue_cone"]`，`road_classes` 应为 `{"blue_cone":"cone_blue"}`；这里角色名 `cone_blue` 固定，左侧标签跟模型一致。不能仅凭“蓝锥桶模型”猜它是YOLO26或一个类别。
导出仍在队友训练电脑完成，需可信训练清单、真实数据集版本和权重SHA，步骤见[模型接入](视觉模型接入与只读测试.md)。只有现成ONNX而没有配套来源记录时，先向训练者取回，或用可信权重重新导出。

## 部署顺序（由现场队友执行）

解压进入包目录，先运行：

```bash
sha256sum -c SHA256SUMS
```

车已停止、网页锁定后，停止 `xt-stcar-console.service`，先备份整个 `~/xt-stcar-console/20260917` 以及已有启动脚本和 `vision.json`。
将 `console/` 七个文件复制到 `~/xt-stcar-console/20260917/`；两个可执行程序权限设为755。
将 `service/run-service.py / start-console.py` 复制到 `~/xt-stcar-console/` 对应位置；现有 systemd 单元、access.json 和录像保持原位。
将模型、配对 provenance 和配置放到独立目录，例如 `~/xt-stcar-vision/`。

从示例创建 `~/xt-stcar-console/vision.json`，填写5个真实绝对路径，`binary` 指向新版 `vision-shadow`，最后把 `enabled` 改为 `true`。运行：

```bash
python3 scripts/check-vision-deployment.py \
  --vision-config "$HOME/xt-stcar-console/vision.json" \
  --release-dir "$HOME/xt-stcar-console/20260917"
```

检查只加载模型然后以EOF退出，**不打开相机、雷达或底盘串口**，也不会启动驾驶台服务。它检查依赖、配对模型和实际原生Session；`--static-only` 只查文件，不能代替原生加载验证。
通过后再启动服务并看日志：

```bash
systemctl --user start xt-stcar-console.service
journalctl --user -u xt-stcar-console.service -n 60 --no-pager
```

浏览器刷新，确认“视觉模型·只读诊断”出现持续新帧，能保存检测JPG。服务启动默认锁定，视觉入口不自主行驶。
`road-perception-sim.json` 仍未实车标定，产生的米制元素只能诊断；模型接通不等于自动驾驶或比赛验收。
需要回退时先停服务，再恢复备份的完整目录和原启动脚本/vision.json，避免新旧文件混用。
