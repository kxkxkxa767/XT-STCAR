# 上游停车目标与实车直道接口

2026-10-06。用户认可第四次实车直道效果，要求把纠偏、降PWM及收油收尾接入正式自动驾驶，并明确停车点由上游传入，不能固定为本次练习场的左转路口。本轮完成通用单目标直道接口；用户最后要求验证、推送GitHub后暂停，因此不部署这份新接口、不继续动力测试。

## 接线

```mermaid
flowchart LR
    A[上游元素与停车请求] --> B[FinalStopGoal 最终姿态与边界]
    B --> C[身份 坐标 时钟 误差 实测预算校验]
    C --> D[墙线纠偏与PWM渐降]
    D --> E[1500收尾与新鲜源位姿验收]
    C --> F[缺项拒绝启动]
```

Rust `OnlineMissionReport.final_stop_goal` 独立于导航的滚动 `MissionOutput::Target.point`。斑马线使用近沿前的完整车体停车点；灯前StopLine表示停车区域，其远沿是禁越边界；终点要求整车入区。最终姿态使用既有共同几何公式，包含目标/Track身份、任务revision、源时刻/期限、误差、完整足迹、停稳和保持要求。未确认、过期、搜索、绕桶、阶段切换或终态不会保留旧正式停车目标。

车端新增 `stop_goal.py`，注册受保护的上游目标并消费最终姿态/边界。正式直道复用已测试的墙线纠偏、PWM下降及`drive→coast→locked`；停车由该目标的实时剩余预算触发，不读取测试`left_junction`作为正式完成条件。前横平面仅保留为通用保护，保护退出、运行到期和中性锁定不改报目标成功。正式完成须新鲜中性采用反馈之后的真实源位姿、位置/朝向/完整车身合格、角点运动上界合格及足够的新源时间；未标定雷达低运动不能单独完成正式停车。

现有 `to-left-junction` 保留为独立试验adapter，没有写入练习场长度、起点、墙坐标、桩位或按时间猜拐点。规则所需的3秒停稳、车辆PWM/几何及资源时限是通用任务/车辆约束，不是赛道特化。

## 输入与调用

服务的三个显式配置入口：

- `--stop-goal-source`：上游持续发布的本机最终目标JSON文件，或包含`final_stop_goal`的任务报告。
- `--stop-goal-contract`：经验证的共同时间映射、位姿原点/误差及实测滑停与起步命令包络。
- `--stop-goal-vehicle-profile`：本车独立实测几何和验证状态。

输入文件必须是同用户拥有、不可被其他用户写入的普通文件，最多64KiB；不跟随符号链接、不打开FIFO，不通过HTTP选择任意路径。上游应原子替换该文件。真实源时刻和目标期限必须随真实新观测更新，文件重读、心跳或状态查询不续源租期；同源时间下改变位姿/几何、倒序、不同身份和几何跳变均拒绝。

上游在一次停车请求期间须保持身份/任务归属一致，直到收到执行完成或明确撤销。当前Rust模拟任务的阶段revision可能在进入Hold时变化，且阶段推进后清除目标；它不能靠修改标签直接变成真实上游feed。正式实车任务应协调执行完成反馈与上游阶段推进。

终点的`completion_permissions`须同时包含与当前目标一致的`goal_id/task_revision/track_id`、已验证的`light_cleared=true`、同一`clock_epoch_id`与新鲜`source_at`。缺项、错误身份或另一任务许可均不能用于当前终点准入与完成；源文件重新读取不会续这份许可。

CLI增加：

```bash
python3 ~/xt-stcar-console/20260917/autonomy-control.py goal-status
python3 ~/xt-stcar-console/20260917/autonomy-control.py goal-straight
# 配套版本已部署、真实源和契约准入通过，并有当次现场授权后才可执行：
python3 ~/xt-stcar-console/20260917/autonomy-control.py goal-straight --pwm 1580 --execute
```

前两条只GET状态，不登记、刷新目标或停止别人的会话。执行入口才显式登记配置好的源，发送紧凑`stop_goal_start`、自己的心跳与源刷新请求；HTTP请求体上限仍2048字节，不能把大目标或任意路径塞进控制消息。目标消息本身不解锁、不续控制心跳。

状态提供`formal_ready`、`formal_rejection`与已注册目标摘要。正式准入按自己的前向/侧向/后方起步窗口检查，与通用短探针的`probe_ready`分别计算，纯查询不改变收尾证据或保持计时。已完成目标不能在同会话中反复触发；人工/故障锁定后不会自行恢复。

## 预算与坐标

停车预算覆盖当前实际速度上界、请求1550–1580后的起步/加速速度上界、源年龄、通信/执行延迟、中性滑停和误差余量。不能因为起点速度0就按零停距给1580脉冲；命令上界没有对应的实测中性包络时拒绝。PWM正常下降最多5/100ms，前进不低于1550，中性1500；coast开始后更新目标也不能恢复正PWM。大航向或横向路线需求明确拒绝直道能力，不用直道假装90°转弯。

Rust用X前/Y左/左转正，Python用X前/Y右/右转正；同一原点的坐标、航向和边界只反射一次，有限侧界也随之反射。之后才能应用经验证外参；原生`heading_left_rad`不能再次反号。当前雷达`at_ms`是整圈发布时间，控制`tick`与Python`monotonic()`亦不是同一纪元；源时钟或位姿原点未绑定时拒绝真实输出。

本车尺量轴距0.25m、雷达前缘0.21m/后缘0.20m、左右轮外沿各0.17m，记录在[实测几何](../config/vehicle-geometry-measured-20261006.json)，不再以厂商默认0.305m代替本车轴距。没有补造测量误差上界、后轴外参、转向曲率/扫掠或滑停标定。

## 当前可用范围

代码接口和执行分支已接入；当前实车**没有合格的正式上游目标、共同时间/位姿/外参及实测停车契约**。Rust导出仍明确`simulation_only=true / physical_control_ready=false / physical_budget_available=false / clock_epoch_id=null`，本车profile也没有导航/停距认证。真实模式默认拒绝启动，不能把这些标志改一下就宣称实车就绪。

车端保留第四次实测的8efc47b独立进程直道版本；本轮通用接口只完成本机代码与GitHub交付，新模块`stop_goal.py`尚未部署。未来部署必须传齐五份Python、匹配Rust桥和入口检查脚本，备份后默认锁定并核对哈希/运行设置。另有新构建的robot runner用于上游报告接口，构建不等于已有真实目标流。

左转和绕桩仍需真实新鲜位姿/航向、曲率响应与完整扫掠/滑停预算、锥桶几何/身份准入，未执行动力测试；不使用模拟PWM表、固定转向时间或练习场坐标作为替代。本轮验证与四次现场结果见[机器记录](vehicle-junction-coast-validation-20261006.json)和[实车修正记录](直道停车与滑行修正-20261006.md)。
