## 可以用于当前工程的思路

| 案例 | 原材料的内容 | 对当前 Rust 工程的作用 |
| --- | --- | --- |
| “RPC规划算法” | 正文实际为 RPP，插件为 RegulatedPurePursuitController；固定前视，避免 RF2O 瞬时速度噪声使前视跳变 | 保持默认 PP，区分定位噪声、路径几何与跟踪误差；前视增大有直线稳定和弯道切角的取舍 |
| 单点导航 | 先核对扫描/地图与实际车头方向，再分别调直线和转弯 | 后续实车按定位、直线、转弯分阶段验收，不能用控制器掩盖坐标系错误 |
| 全局规划切换 | Smac Hybrid 在搜索中考虑航向和转弯半径；NavFn/ThetaStar 提供不同几何路径 | 优先检查短目标、路线和终端候选的运动学覆盖；二维连通不等于车体能转过去 |
| 局部规划切换 | MPPI 的 Ackermann 模型和有限时域控制序列；DWB 采样速度 | 可借鉴有界候选探索，但每条候选仍须满足当前转向变化率、完整车体和停车认证，不能直接替换或增加预算 |
| 多点导航 | CSV 保存地图坐标，`go.py` 提交 NavigateThroughPoses | 仅可作为旧 Fixed 模式对照；不替代在线估计元素位置、持续更新短目标 |
| 建图切换 | 激光里程计、IMU、地图坐标变换的职责与建图配置 | 提醒检查传感器时间和坐标链；不提供停车区、终点的语义距离 |
| 串口绑定 | 按真实设备连接识别并设置稳定设备名 | 待接车时核验；不能从教程端口顺序推定本车实际设备 |

## 不能照搬的参数与资料差异

- RPP 示例 `desired_linear_vel=0.55`、`lookahead_dist=1.2`，并且 `use_collision_detection=false`；这与当前速度和安全约束不同，不作为推荐值。教程的效果提升百分比没有在本工程验证。
- 单点教程示例最小速度阈值0.30高于期望速度0.27，与其自身“阈值不超过期望速度”的说明不一致。保留为原资料问题，不修改当前配置来迎合它。
- MPPI **文档**为56步、0.05秒、1600批、最高速度0.27、最小转弯半径0.6；原始 ZIP 的 **nav_mppi.yaml** 实际为40步、0.05秒、500批、最高速度0.55、最小转弯半径1.0。文档和出厂配置不是同一组实验参数，均没有当前车端实时性能证据。
- ZIP 中 `Run_nav.launch.py` 默认引用 `nav_navfn.yaml`，但同一 ZIP 的配置目录没有该文件，仅有 `nav_carto.yaml`、`nav_mppi.yaml`、`nav_Smac.yaml`、`nav_ThetaStar.yaml` 等。因此不能把教程启动命令当作完整可运行交付，也不在本轮替用户修补厂商原件。
- Smac 示例允许 REEDS_SHEPP 搜索；当前任务不据此放开倒车。较大的搜索时限、0.4/0.6米到达容差也不能用来替换原预算或比赛检查。
- CSV 路点与 RViz 地图截图没有给出官方比赛停车区/终点的可见图案协议；灯色本身仍不能提供停车距离。

## 本轮用于下一步的结论

[真实33.260秒首拒](小场异步首拒快照.md)发生在跟踪 rollout 之前：17段拒绝均涉及有限停车线侧带，端点车体余量已经不足，单独缩紧扫掠管不能认证这些候选。因此借鉴案例中的运动学规划思路，下一步在同一真实夹具、原净空/制动预留/总预算下检查：

1. 当前在线短弧目标和候选路线是否过早贴近新观测边界。
2. 实际曲率起点下，终端初猜和恢复搜索能否覆盖另一条可认证路线。
3. 任何可行候选是否仍通过真实 source/history/lease 和异步最终采用门，再检查整场是否改善。

这些是有证据支持的后续实验方向，不是已实现的算法改进。当前小场与在线正常整场仍未验收；不因本轮测试通过更改旧失败矩阵。
