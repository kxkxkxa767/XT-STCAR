# 路径连续性与性能回归（v9）

本轮依据[第九份复核意见](https://chatgpt.com/share/6aa89fa3-3894-83e8-afe8-45451cbbc42f)
及用户本地 `XT-STCAR_a623638_review.zip`。基线为
`a6236380a68431342ab9e76f468c587c9dd775f3`，对照为 `7d28761c40f7d7e69a8ac77977f5b6710dd5a0c6`。
分享4630字符正文已完整读取；原ZIP的Python算术脚本在work副本运行，结果与提供文件一致。
这份外部材料没有运行Rust或实车，不能当作控制器重放。原ZIP不修改、不提交。

## 问题与归因

固定实验LQR、输入延迟 `[40,60] ms`、采用偏移 `[3,7,9] ms`：
旧版54.447秒、10.317616米；v8为88.647秒、16.515558米。
两者实际Stop命令均4513ms，增加的路程主要发生在灯前阶段：
24.600秒/4.361517米变为59.400秒/10.590409米。Stop命令时长不等于物理静止时长。

消融分别使用原版、原版仅调整候选检查顺序、v8完整修复版，移植同一只读观察器。
三个变体各有独立源码和Cargo target，避免历史文件时间戳让Cargo错误复用产物。
旧版与仅换顺序版的285条实际命令及对应车辆状态逐条一致；
前瞻投影1,681,009→1,636,944，预扣区间72,896,820→70,984,237，约减少2.62%。
这是固定工况的工作计数，不是CPU或目标板实时性结论；旧时基只用于离线归因。
生产共享时基及最终poll检查保持。来源、补丁和复现见[消融证据](motion-v9-ablation.json)。

45,360ms规划（源45,300ms）发生明确的同目标路线加长：灯前目标(5.55,2.5)、朝向0，
车体参考偏离触发重建；按该拍当前姿态计算的旧剩余路线0.502864576米，
新路线4.910317092米，增加4.407452516米。该拍未耗尽节点/终端额度，未启用连续恢复。
这和“返回路径首点/点数不同”有区别，比较的是同一目标、同一当前状态的剩余路线。
更早锥桶通过点也生成过长路径，但随后立即推进任务；生成长度不能直接算作实际已行驶距离。

## 预先固定的离线性能门

预算文件为
[`crates/runner/examples/fixtures/motion-v9-performance-budget.json`](../crates/runner/examples/fixtures/motion-v9-performance-budget.json)，
在本轮生产修复试验之前固定，含时间、来源报告哈希和逐组参照，不根据修复后的成绩回调。
各组选择v7/v8相同时序中耗时较短的已完成场作为参照；不采用失败场成绩。

- 整场时间与实际距离不超过参照的110%，毫秒上限向上取整。
- 每阶段时长不超过参照加 `max(1000ms, 10%)`。
- 实际Stop命令累计时长不超过参照加1000ms，包含启动和最终制动。
- 八场完整、观察轨迹未截断和原安全/比赛检查仍需分别通过。

坏工况的整场上限为59,892ms、11.349377645米，灯前阶段上限27,060ms。
对v8已提交结果应用此门，恰好是这场的整场时间、距离及灯前时长失败，其余七场通过。
新增Rust回归确认“已完成但长绕路”仍会失败，缺失/重复工况、缺失/负数指标也不能冒充快速通过。

门控只在专用例程全部仿真结束后读取结果，控制器不读取这份预算。
`support/performance_gate.rs` 检查结果并输出 `performance_gate`，性能不达标时保留完整JSON并非零退出。
它不会改变速度、路径、候选评分、Q/R、碰撞余量、任务门限、共享时基或搜索额度。
默认运行不记录逐tick大轨迹，诊断保存在有界内存，结束后输出；eMMC策略及控制频率不变。

```bash
# Mac，固定八场；非零退出时检查报告，不提高预算来制造通过
mkdir -p work
cargo run --release --locked --offline -p xt-stcar-robot-runner --example async_timing_matrix > work/async-timing-matrix.json 2> work/async-timing-matrix.stderr.log
cargo test --locked --offline -p xt-stcar-robot-runner --example async_timing_matrix
```

PP保持默认，LQR保持实验；本轮只做主机离线模型与交叉链接，暂不接车，不执行RISC-V目标程序。
功能仿真等待worker时暂停逻辑时钟，完整成绩不证明真实计算截止时间或实车性能。

## 修正的具体位置

根因窗口继续向前追到45,160ms：45,040ms选中候选的末端初值对应预测的45,140ms状态，
下一拍却实际在45,160ms开始。原冷启动和未经推进的旧初值都耗尽各自8次迭代；
以相对预测状态的约0.0036米正向位移推进初猜，可以在原约束内重新求出短连接。
这说明初猜需要与实际规划状态衔接，不需要撤销共享采用时基或扩大终端预算。

- `robot-core/src/navigation/continuity.rs` 缓存候选预测的下一姿态/时刻。普通成功路径仍先走原冷启动及原旧初值；
  原方法失败且额度剩余时，尝试按正向位移推进初猜。早到/负向位移保留旧初值，无效/耗尽段提示弃用。
  位移是数值初猜调整量，不是实际行驶弧长或里程计读数；预测锚点也不写入真实采用时钟。
- 只有这样恢复成功的短连接族才优先接续。`navigation.rs` 的候选仍先通过当前采用约束、原rollout、多源后备和终端认证，
  再优先选择认证接续、最接近已认证首段曲率者，最后按原评分比较。**恢复族内候选优先级确实改变**，
  不应概括为所有评分/选择不变；普通成功族和原冷候选全失败后的恢复轮保持原规则。
- `terminal.rs` 的 `used_seed` 标记来自实际求解分支，区分冷解与接续，不由诊断计数控制。
  每次重用都从当前姿态、执行曲率、Grid和携带的误差界重新积分认证；新障碍/边界可否决提示。
  目标/朝向、到达策略、边界或任务停驻变化清理提示，规划不代替最终采用。
- 同一拍仍共享256次求解、1024次迭代、65536份预扣样本，单次最多8迭代、节点上限40000；
  继续保留原一次接续预留，没有reset总账或把搜索费用移出计数。
  原Q/R、速度/转向/车体/间隙/误差包络、停稳/绿灯/终点和真实poll/lease均保持。
- 新可选 `route_length_change` 只在同目标、旧缓存可用、车体参考偏离且重建成功时输出旧剩余/新路线米数。
  两者使用同一当前姿态及原最多1米局部进度搜索，不跨回环找最近点；缺失表示没有这份比较，不能证明没有绕路。
  它只作诊断，默认无逐tick落盘，也不改变控制频率；原默认日志100000字节上限回归通过。

## 舍弃的方案与最终验收

[试验记录](motion-v9-experiments.json)保留实际失败。只保留旧seed无效，单做预测锚点调整仍需81.043秒；
广泛优先warm虽使坏场变短，却令PP和同步LQR退化。只在原失败后补warm可以恢复坏场，
但另一组LQR实际Stop/灯前阶段越过预声明门；只保存接续标记又出现普通停车超过10秒。
最终只保护已恢复族，并在完整认证后保持其第一段动作方向，才使全部固定工况通过。
这些试验促成有限范围修复，未按延迟数组选择控制分支，也未改验收预算。
