## 缺口身份与用户纠正

用户明确：绕桶时识别灯道挡板缺口，灯按缺口摆放，应保留提前定位。现有程序在第一桶阶段学习缺口距端墙的偏移，第二桶阶段并不重新选择缺口，而是重新选择“远墙”换算当前位置。y83出第二桶时该参考跳远约1.2 m，之后又跳到近面；这是已知失效。尚无充分证据把那组远处回波认定为斑马线挡板，不能把用户的合理假设写成已证实事实。提速会缩短纠错和刹车余地，但不能据一轮断言低速掩盖了全部问题。

## y84／191 修改

运行逻辑只改Rust比赛分支，基线是已装车 `claude-turn190`。

1. 保留第一桶阶段的同一缺口探测；同时记录缺口与真实第一桶心的轴向偏移。两桶同时有新鲜支撑时，把这个偏移换到第二桶。出第二桶后在独立的跟踪器副本中继续观察同一桶，接续缺口位置；不重新绑定路线目标或开启路线恢复。短缺测用既有1 s IMU桥接，读取预测不刷新真观测时间；没有建立桶间关联时仍保留原端墙回退，并输出来源诊断。真实灯架仍负责后续校正。没有固定场地坐标、桶距或板长。
2. 灯段速度滤波首次建立时，用同帧真实桶心测速初始化；避免第一组发生位移跳变的灯架距离直接以权重1变成车速。已有有效滤波状态仍按原规则校正。
3. 活跃的1300制动不能被“已过线但未见红”或预告撤销分支取消。原静止结束条件、暂停/故障输出、光电柱与门架分类规则均保持。
4. 斑马线放行仍用1600起步，已有速度加响应余推达到入弯预算后接1570；按当前切点和实测速距作一次收油，接1550并锁定到第一桶弯内。状态跨目标交接保留，切点抖远不能重新升1570。1570的动力预测包含基础响应和原地面补偿。不是全路段无条件替换。

用户说“这轮改好后仿真一下看看”，本次离线仿真按该新授权执行，覆盖此前不主动仿真的约定。没有新的实车发车授权。

## 仿真方法与结果

使用现有 `surface_sim`、真实Rust控制器和监管层；y83从HEAD的已提交源导出，y84用当前候选，两者使用相同物理模型、布局和随机种子。28组包括缺口处/下游灯位、0.9 m车道、规则范围1–2 m车道、转向响应、地面阻力和制动/1530响应敏感性。场地长宽来自原生成器5–8 m、4–6 m范围。光电立柱关闭，对应当前实车未见立柱的证据，不能代表正式场地必然没有立柱。

发现旧模型把低于1550的1530夹到1550，且1300仍为常减速度，不能准确评价本次低档/制动。保留旧模型结果作诊断后，增加离线模型的可选速度制动项（默认0保持旧模型行为），采用 `config/track-spec-sim-20261112.json`：1300用已经保存的y79灯段b(v)=0.668863+0.315219v；1530的0.4 m/s稳定速度、2.5 s响应是明确假设，另测0.2/0.6 m/s及相应响应。该稳定速度没有实测，不能称作已标定。两版共享模型，不以候选结果反调模型。摄像仍是理想语义和0.60–6 m硬可见范围；电调统一0.056 s延迟仍与实测1300约0.1 s不同。

第一桶阶段未出现1550后回到1570；最小车身至桶间隙由y83的0.0966 m变成y84的0.0708 m，发生在一组宽场地布局，余量变小必须保留为实测关注项。斑马线放行到出第一桶的样本中位数4.00→3.95 s，不是配对中位改善，也不代表实车圈时收益。独立桶参考在28组入口均启用；模型通过不能证明真实远墙回波问题已彻底消失。

最终证据：`work/codex-y84-fix-20261112/sim-comparison-v3/`（两版逐例配置、trace、summary、results、stage-metrics）。`compare_sim.py`在同一工作目录。v1的部分0.9命名配置发生并发覆盖，作废；v2使用旧物理模型及测速初始化修正前代码，非最终结果。v3是本文统计依据。
