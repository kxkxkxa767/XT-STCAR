## 2. 下一步（按优先级）

### ① 两桶之间的过渡直道提速

用户 11-02：“感觉第一段没有多大的收益，我觉得主要可以提速的是第一个桶到第二个桶的过渡，那个距离很大而且是直道”。

**现状**

- 过渡段对应 route_stage `open_transfer`，从过第一个桶到第二个桶交接。用时 y22 1.12 s，y24 1.28 s。
- 全程 1550。有读数的帧里车速约 1.24–1.33 m/s，进第二圈约 1.24 m/s（y22）。
- 大约一半的帧 `open_feedback.speed_mps` 是 None。这个速度由前方距离 `front_range_m` 的差分得到，而前方目标在隔板端头和远墙之间来回跳。y24 的读数依次是 4.20→3.82→5.88→5.52→2.92 m，所以测不出速度。
- y23/y24 的 `_straight_motor` 在没有速度、或速度超过上限时都给 1550。上限 `STRAIGHT_TRANSFER_MPS` = 1.1，比实际的 1.3 还低，所以过渡段其实没提速。

**怎么做**

1. 先给过渡段一个稳定的车速。例如沿通道轴线，用隔板或墙的逐帧位移来算。
2. 在直的部分推 1590/1600，第二圈转弯前降回进圈速度：y22 约 1.24 m/s 是好的。仿真里 1.45 m/s 进第二圈撞了外墙；仿真不准，但说明进圈速度不能高太多。

**先估一下收益**

- 按 y22 过渡段约 1.4–1.5 m 的路程算：只靠滑行减速（.6 m/s²）几乎没收益；用 1300 刹车（约 1.5 m/s²）大概能省 .1–.3 s。
- 物理上的直道可能比 `open_transfer` 阶段长，可能包括第一圈出口和第二圈接近。先用 `scripts/trial-map.py` 看轨迹，确认直的部分从哪到哪，再定推力区间。

**刹车注意**

- 电调是双向带刹车模式：前进中给低于 1500 是刹车；刹车后回到 1500，再给低于 1500 就会**倒车**。
- 所以现在一次运行只在终点刹一次，由 `_lane_brake_end` 记住刹过了。
- 如果过渡段也要刹车，两次刹车之间必须有前进动力（大于 1500）。按一般电调的逻辑，这样下一次低于中位仍然是刹车，但这台车没验证过，要先在车上测一次：过渡段刹一次，看终点那次是刹车还是倒车。
- 服务端和监管层现在只在过灯后的灯区放行 1300，过渡段要用就得在两处都加上。

- `vehicle-bridge`：由 route-engine 启动，代码在 `crates/runner` 和 `crates/robot-core`。它是唯一的输出通道，不能删。

旁边还有：

- `scripts/vision-log.py`：在 CPU 上跑 YOLO（race4.onnx，约 3.65 帧/s，推理约 233 ms）。每帧把红灯分数、绿灯分数、斑马线分数和距离写进 `--light-state` 文件，`route-engine race --light-state` 读这个文件。
- `scripts/race-trial.py`：车上的助手。固定参数为累计驾驶预算 40 s、预打舵 1670、就绪保持 1 s。
- `scripts/start-round.py`：在 Mac 上启动一轮。

### Python 和 Rust 要一起改

Python 是参考实现，车上跑的是 Rust。**两边必须一起改，并且逐位一致**。

路线逻辑：`web/vehicle-console/maneuver_sequence.py` ↔ `route-engine/src/maneuver*.rs`。

| 功能 | Python | Rust |
|---|---|---|
| 起步直道、斑马线后、接近第一个桶 | `_start_governor`、`_start_allowed_speed`、`_straight_motor` | `maneuver_post.rs`、`maneuver_open.rs` |
| 过渡段 | `_transfer_motor`，在 open_transfer 阶段由 `_route_motor` 返回 | `maneuver_open.rs`、`maneuver.rs` |
| 斑马线 | `_crosswalk_observe` 等 | `maneuver_crosswalk.rs` |
| 红绿灯：龙门架、灯前停车、红灯锁定 | `_light_red_hold` 等 | `maneuver_light.rs`、`maneuver_post.rs` |
| 灯区、终点停车、刹车 | `_lane_goal_control`、`_lane_worst_gap`、`_lane_stop`、`_coast_fit_window` | `maneuver_post.rs` |
| 质量等待 | — | `maneuver_wait.rs` |

- **新加的状态字段**要同时加进 `route-engine/src/dump.rs`。`tests/test_route_96_engine.py` 靠它对比 Python 和 Rust。
- **电机白名单**按阶段分：Python 在 `web/vehicle-console/server.py` 的 `allowed_motors`，Rust 在 `route-engine/src/supervisor.rs`。新的 PWM 值不加进去，监管层会停跑。
- **桥**：`crates/robot-core/src/teleop.rs`，电机 1000–2000，舵机 1200–1800。改了 crates，构建时要加 `--rebuild-bridge`。

### 关键常数（maneuver_sequence.py）

- **斑马线**：
  - 等 3 s；目标停在白条前 .15 m，底线 .08 m；
  - 瞄准用断电延迟 .2 s、减速度 .6 m/s²；
  - 保护用反应时间 .3 s、减速度 .6 m/s²。
  - 定位：最新一帧比中位数那帧更准、并且两者一致时，用最新那帧。
  - 如果没在斑马线前停下，就在第一个弯前停车等 3 s 兜底。
- **红绿灯**：
  - 停车区 1 m；目标车头离灯线 .45 m，底线 .05 m；
  - 识别阈值：红灯 ≥ .25，绿灯 ≥ .5；
  - 放行：先红后绿就走；一直没看到灯，4 s 后放行；第一次看到红灯后 10.5 s 放行；最长等 12 s。
- **终点**：
  - 目标离板 .25 m；
  - 刹车条件：离板 1.2 m 以内、车速 ≥ .3 m/s；最长刹 1.5 s，每次运行只刹一次。
- **直道**：
  - 1590 按 3 m/s² 估算，断电延迟 .3 s；
  - 进圈速度上限 1.1 m/s；
  - 超过上限 .15 m/s 以上才断电，不到就用 1550 保持。
- **第一圈**：左舵输出增益 1.2（`FIRST_LOOP_STEER_GAIN`），因为车实际转得比标定紧 1.2–1.4 倍。

## 6. 比赛规则要点

规则原文是根目录的赛项三规则 PDF。

- **顺序**：起步 → 斑马线停车（≥ 3 s）→ 左转 → 第一个桶逆时针 → 第二个桶顺时针（走 S 形，不是绕整圈）→ 右转进灯区 → 红绿灯 → 终点区停车。
- **斑马线**：不停车 +30 s。
- **红绿灯**（2.4.2(4)）：
  - 光电传感器在灯前 1 m，传感器和灯之间是停车区。
  - 车经过传感器后触发 3–10 s 的红灯。红灯亮起要立即停车，停在区内等到绿灯。
  - 罚时：绿灯前通行 +30 s；停车时任一车轮在区外 +20 s；未停车 +50 s。
- **成绩**：T = 比赛用时 − 红灯停车用时 + 罚时。
- **撞桶**：扣 20 s，但继续跑。用户：“桶撞到了也继续比赛，仅限于桶”。
- **场地**：是一个范围，长约 5–8 m、宽 4–6 m，人行道和红绿灯的位置随机。

## 7. 实车测得的数据

都是在瓷砖地上测的，换地面要重测。

- **滑行**：减速度约 .6 m/s²（y15–y19 在线拟合为 .565–.603）。断电延迟 0–.3 s，平均约 .2 s。
- **起步加速**：
  - 1600 从静止起步，通电期间约 4 m/s²，.47–.48 s 后断电，峰值约 1.87–1.9 m/s。
  - 1580：.5 s 内从 .1 加到 1.34 m/s，峰值约 1.4 m/s。
  - 1560：峰值约 .92 m/s。
- **1300 刹车**：刚生效时约 1.5 m/s² 以上，之后约 .6–.9 m/s²。y22 刹了 1.28 s，从 1.475 m/s 降到 .40 m/s。
- **电调**：双向带刹车模式（见第2节①）。10-16 试过 1450 刹 .3 s、1400 刹 .5 s，在电调延迟内都没起作用。
- **1550 的车速**：过渡段约 1.24–1.33 m/s；第一圈进圈约 1.0 m/s（y22）。
- **相机测斑马线距离**：
  - 在 1.5–2 m 处，误差每轮都不同，±.15–.38 m；近于 .6 m 时约 −.09 m。
  - 俯仰角每天会变，用户说“没动过”也会变。不要按一天的数据重新标定。
- **识别**：约 3.65 帧/s。race4 对斑马线在约 1.75 m 以内可靠。
- **仿真车**：滑行比真车长约 35%，转向也不同。仿真的结论不可信。
- **练习赛道起点到斑马线**：白条近边到车头的距离 = 2.748 − 后方雷达读数（11-01 用户量的）。只能用于分析，不能写进代码。

## 8. 怎么分析一轮

### 证据目录

位置：`$W/left-cone-trial-<日期>-yK/`，同一版重跑是 -yK-2……

- `run/feedback.jsonl`：每行一个控制帧，约每 150 ms 保存一次。主要字段：
  - `elapsed_s`
  - `lidar.scan.ranges`：360 格，bin i 表示自正前方顺时针 i 度，后方是 176–184。
  - `state.autonomy.active.turn`：包括 `route_stage`、`motor`、`crosswalk_state`、`light_stop_state`、`start_lane_feedback`、`open_feedback`、`lane_feedback`、`light_feedback` 等。
- `run/light.jsonl`、`light-state.json`：灯的状态。
- `vision/`：识别帧。
- `race-stdout.txt`、`helper-result.json`、`run/summary.json`：运行输出和摘要。

### 方法

- **阶段时间线**：打印 `route_stage` / `light_stop_state` / `crosswalk_state` 每次切换的时刻。第1节的表就是这样算出来的。
- **现成工具**：
  - `scripts/trial-timeline.py`：逐帧决策。
  - `scripts/trial-map.py`：ICP 重建轨迹、车速、曲率，输出 PNG。
  - `work/y11-sim/analyze_run.py <证据目录>/run`：斑马线的断电和停车。
  - `work/y15-sim/` 下的 after_green.py、light_approach.py、fit_lag.py、lane_cut_lag.py 等：灯前、过灯后、断电延迟。
- **里程**：斑马线段最准的是后方雷达（bins 176–184 的中位数）；灯区用前方终点板加后方。

## 9. 历史教训

- 先确认输入信号（车速、标定）是对的，再去调门槛。y5–y9 的起步车速来自 7–8 m 外跳动的挡板；相机俯仰偏了 8–15 px。
- 保护模型太保守，车就会切得早、停得远，然后再点动。例子：y12 停在白条前 .9 m；y19 灯前点动 3 次。要用实测的断电延迟和减速度。
- 不要用仿真去否定实车上好用的东西。用户的观察（他看现场和视频）优先。
