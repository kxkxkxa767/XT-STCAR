# 运动控制设计与对比

核对日期：2026-09-09。全部实现与实验为 Rust 离线代码；没有连接车辆或执行电机输出。

分享中引用的文件编号不作为工程证据，以下判断另行对照当前源码及算法原始资料。

| 建议 | 本轮处理与理由 |
|---|---|
| 保留 A*、车模型搜索和候选轨迹预测 | 采用。它们处理路线可达性、车体碰撞及约束，换跟踪算法不能取消这些检查 |
| 抽出 PathTracker，比较 Pure Pursuit 与 LQR | 已实现 `robot-core/src/tracking.rs`，默认仍为 Pure Pursuit；实验 LQR 经同一导航限幅、候选预测和安全输出通路 |
| 用 LQR 替换当前默认 | 暂不替换。需要比较全场成功率、转向响应、误差和计算截止时间；算法名称本身不能证明提升 |
| 速度前馈表加 PI | 当前只有静态标定表。PI 应在可靠速度反馈、执行器模型和 PWM 标定之后接入；不能把低频带延迟的激光速度直接当高速轮速 |
| N10 与 IMU 做 EKF/ESKF | 有价值，但本轮未实现融合。先补共同时间轴、扫描去畸变、IMU 外参/偏置、观测噪声及退化处理；ICP 的 quality 不是协方差 |
| MPC / NMPC | 保留未来扩展入口，没有引入求解器。板卡规格不能证明本工程在 YOLO 并发负载下的最坏计算时延 |

分享引用的舵机 `0.16～0.18 s/60°` 是舵机轴标称值，不能直接换算车轮转角、曲率变化率或整车响应延迟。
当前模拟的轴心、足迹、曲率上限和 `4.0 m⁻¹/s` 转向变化率都不是实车标定。

## 模块、单位与控制通路

| 层 | Rust 文件（相对工程根目录） | 输入 → 输出与职责 |
|---|---|---|
| 状态估计 | `crates/robot-core/src/localization.rs`、`crates/runner/src/laser_pose.rs` | 整圈点云、TF、已知初始位姿 → 带源时间和质量的平面 ICP 位姿；尚无 IMU 融合 |
| 比赛任务 | `crates/robot-core/src/mission.rs` | 位姿与道路观察 → 目标点、限速、目标朝向或 Stop；管理斑马线、灯前和终点 |
| 规划与约束 | `crates/robot-core/src/navigation.rs` | 位姿、障碍、任务目标 → 有界网格/车模型搜索、路径进度、候选预测及制动检查 |
| 路径跟踪 | `crates/robot-core/src/tracking.rs` | 原始参考路径、局部进度、位姿、速度 → 前视目标与期望曲率；PP 默认，LQR 显式选择 |
| 安全状态机 | `crates/robot-core/src/safety.rs`、`crates/runner/src/autonomy.rs` | 指令及源时间健康状态 → 检查后的 Drive/Stop；异常 Fault 锁存 |
| 周期命令期限 | `crates/runner/src/control_runtime.rs` | 最新计算结果 → 有效期内命令；必须使用 `poll().command`，不能直接发送诊断字段 `latest` |
| 执行器映射 | `crates/robot-core/src/protocol/calibrated_chassis.rs` | m/s 与 m⁻¹ → 合成速度/曲率表插值、PWM 范围检查；只预览，没有物理发送接口 |
| 被控对象与验证 | `crates/runner/src/simulation.rs` | 检查后的命令 → 有加减速、转向变化率和 Stop 回中的模拟运动反馈 |
| 单独 A/B 实验 | `crates/robot-core/examples/tracking_comparison.rs` | 确定性参考路径与合成执行器 → 一份 JSON 指标，不执行比赛状态机或避障 |
| 全场 A/B 实验 | `crates/runner/examples/motion_comparison.rs` | 同一完整合成比赛分别选择 PP/LQR，保留完成与失败摘要 |

统一使用车体 x 向前、y 向左，世界 yaw 逆时针为正。`MotionIntent.speed_mps` 是线速度，
`curvature_per_m` 是带符号路径曲率；模型中 `yaw_rate = speed × curvature`。
它们不是厂商 Twist.angular.z 的经验值，也不是直接舵角或 PWM。未来有实测轴距 L 后，
理想单轨几何可用 `delta = atan(L × curvature)`，实际执行仍需舵机连杆、机械中位及左右标定。
停车时不能用 `yaw_rate / speed` 推算转向；无编码器也不能用命令速度伪造速度反馈。

处理顺序为：任务目标 → 车模型路线 → PathTracker → 曲率/变化率限幅与速度候选 → 碰撞/停车可达域检查 → Safety → 输出。
PathTracker 只产生期望，不拥有发车权限。输入或参考几何不合法时导航请求 Stop。
更换算法不刷新源时间、命令租期或任务停车计时。

本轮另行复核前进/速度边界、加减速、Stop、源时间看门狗与 PWM 表，没有发现证据充分的新缺陷。
新增接口测试中统一了极小速度测量容差：导航原有±1e-6m/s容差通过后，仅对跟踪器输入归零/夹限，
不因浮点微小负值使默认 PP 额外停车；更大负速度仍拒绝。非法配置、未知算法和多余字段均拒绝。
导航保存上一目标曲率而非实测转角，普通侧向限值只约束候选 `v²|k|`；执行器动态过渡尚未验证。
Stop 会把目标曲率设为0，实际舵机可逐步回中，停车圆盘按任意中间转向的可达范围保守覆盖；
其前提仍是实际制动不弱于配置，不构成实车制动保证。

## Pure Pursuit 与实验 LQR

Pure Pursuit 的目标点选法及 `k = 2*y_body / (x_body² + y_body²)` 保持原实现；
几何依据为 [Coulter 的 CMU 技术报告](https://publications.ri.cmu.edu/implementation-of-the-pure-pursuit-path-tracking-algorithm)。
目标在后方或退化时不能产生原地旋转。

LQR 直接作用于曲率偏差，不猜测实际轴距。状态为横向误差 `e_y` 和航向误差 `e_heading`，
在固定正速度、直线附近采用 `e_y_dot = v*e_heading`、`e_heading_dot = v*delta_k`。
对角代价 Q 与正标量 R 的连续时间解为：

```text
k_y       = sqrt(q_lateral / r_curvature)
k_heading = sqrt(q_heading / r_curvature + 2*k_y)
k_cmd     = k_reference - k_y*e_y - k_heading*e_heading
```

闭式系数由本工程将上述模型代入连续 Riccati 方程得到；一般理论见 [MIT LQR 讲义](https://underactuated.mit.edu/lqr.html)。
参考曲率从真实路径相邻点估计，误差相对局部路径投影；不能先把路径首点改成车当前位置，否则横向误差会被抹掉。
只检查进度附近的参考段，避免在交叉路线上跳到另一分支。

这是直线附近模型加曲率前馈，没有求解弯道 Frenet 完整线性化、离散 Riccati 方程、执行器延迟或约束最优控制。
对弯道、离散周期、限幅及变化速度不作全局稳定性证明。低速退回 PP；超出配置误差范围或参考几何无效则请求 Stop，
不能将它描述成已验证的高速自动驾驶控制器。Q/R 数字带各误差量单位的权重，不能直接照搬别车。

## 如何离线复现

在 Mac 工程根目录运行，无设备 I/O：

```bash
cargo run --release --locked --offline -p xt-stcar-robot-core --example tracking_comparison
cargo run --release --locked --offline -p xt-stcar-robot-runner --example motion_comparison
cargo run --locked --offline --bin xt-stcar-robot -- autonomy-sim --config config/competition-sim.json
```

旧配置省略 `navigation.tracking` 时自动选择 PP，也可显式写 `{"kind":"pure_pursuit"}`。
LQR 必须在模拟配置副本的 `autonomy.navigation.tracking` 中显式选择，例如：

```json
{
  "kind": "lqr",
  "q_lateral": 4.0,
  "q_heading": 2.0,
  "r_curvature": 1.0,
  "min_speed_mps": 0.03,
  "max_heading_error_rad": 0.7,
  "max_lateral_error_m": 0.5
}
```

这些权重仅供离线对比；外层 `simulation_only=true`、`measurement_status=unverified` 仍须保留。
同步快照回放配置的对应位置是 `navigation.tracking`，不是多一层 `autonomy`。
默认例程只向 stdout 输出结果；有诊断需求再保存摘要，算法循环不落盘、不新增高频 eMMC 写入。

## 本轮离线结果

原始数值见 [跟踪层 JSON](motion-control-tracking-comparison.json) 与 [全场 JSON](motion-control-competition-comparison.json)。
跟踪层为 0.3m/s、40ms 更新、最大曲率2m⁻¹、实际曲率变化率4m⁻¹/s、理想同步位姿；
每条路径分别施加0/200ms假定指令延迟，两个跟踪器共16次均进入终点容差。此实验到终点即结束，单独不验证停车。

无附加延迟时，横向 RMS 如下（米；包含初始偏差恢复过程）：

| 合成参考路径 | PP | LQR |
|---|---:|---:|
| 直线，初始横向偏差0.25m | 0.07082 | 0.10240 |
| 直线，初始航向偏差0.18rad | 0.01211 | 0.02619 |
| 半径2.2m四分之一圆及切线尾段 | 0.03917 | 0.06146 |
| 振幅0.55m的S弯 | 0.03468 | 0.05252 |

该组权重下 LQR 校正较温和，请求曲率变化率较低，但横向 RMS 更高；不能从这些数据得出 LQR 更适合本车。
延迟参数是人为假设，不能用来推导实车舵机性能。

在完整合成比赛中，PP保持55.3s完成、斑马线3000ms、绿灯确认300ms、最小锥桶间隙约0.301m、终点实际模拟速度0。
同一场景和上述 LQR 参数在绕锥桶阶段停止，27.9s触发“ordinary stop exceeded 10 seconds”，最终模拟速度0，未完成比赛。
这说明单独路径指标不能代替任务/规划/避障整体对比。本轮不调高故障期限、不放宽碰撞检查来使实验算法通过。
LQR继续保留为显式实验项；下一步需诊断参考曲率连续性、候选评分与路线可达域之间的配合，完成全场回归后再考虑默认选择。

## 接车后的验证顺序

先核实底盘结构、原点/轴距/足迹、转向中位及左右曲率、速度与制动语义；
再测传感器源时间、扫描运动畸变、定位在直线/转弯/低纹理处的误差与失效行为。
速度 PI 的后续实现需要反馈源年龄限制、按新样本积分、限幅抗饱和、Stop/Fault 清积分，
以及不越过停止/倒车死区的 PWM 修正范围。慢速激光更新不能靠重复采样制造高频反馈。

之后才比较同一地图、同一速度和载荷下 PP/LQR 的完成率、横向/航向误差、转向振荡、停车误差与最小障碍间隙；
给相机推理、定位、规划及输出同时施加负载，记录目标板计算延迟分位数、超时次数和 MCU 断链停车。
这些是后续实测入口，不是本轮已完成的车端测试。
