## 斑马线位置

按用户指定的线下赛尺寸图：发车区 0.8 m，发车区前边界至斑马线靠起点的后沿 2 m，纸条沿行驶方向长 0.297 m，起步通道长 3.2 m。

- 后沿距起点后挡板：2.8 m。
- 另一边距起点后挡板：3.097 m。
- 两边到通道侧挡板端头的距离：0.4 m、0.103 m。

Rust 把后沿固定在既有后挡板里程坐标上。车头余距 = 2.8 − 雷达到后挡板的实测距离 − 雷达到车头的 0.2 m。随后继续按既有雷达里程更新；不要求每次将车摆在发车区的同一位置，也不用运行秒数猜位置。

该预设只在既有里程确实选择起点后挡板时使用；不能把前方挡板的里程当后挡板坐标。没有取得后挡板参考时，沿用原视觉定位和既有回退行为。配置和事件明确记录 `field_test_dimensions_from_start_rear_wall`，不会伪装为 YOLO 检测。

## 灯和采图

初期灯未供电时，仍按 y94 的实际门架、缺口与刹车逻辑停到灯前，从原有停稳登记时刻开始固定等待 10 s。这个测试模式忽略灯色对车辆控制的影响，但保留真实检测结果。

视觉进程逐帧保存未画框的画面，JPEG 质量 95，单轮上限 1500 张，包含漏检帧。修复 `save_every=1` 时原取模条件不能保存漏检帧的问题；检测日志同时保留图像推算距离和单调时钟，供后续与固定位置、雷达位移对齐比较。

## 操作

以下配置命令都在车端 SSH 终端执行，本身不会发车：

```bash
start --test                 # 启用上述尺寸、固定等10秒、逐帧采图
start --test-status          # 查看配置
start --test-lights vision   # 灯供电并开始验证识别时，恢复原灯色放行逻辑
start --normal               # 关闭整个测试预设，恢复原视觉斑马线与灯色流程
```

配置保存在车端工程 `field-test.json`，每轮复制进独立证据目录。实际发车仍为摆车、复位之后的单独一次 `start`。
