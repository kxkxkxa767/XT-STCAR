# 底盘物理量到 PWM 的 Rust 预览

2026-09-08。本模块把 Controller 的 `MotionOutput` 转成已有 `PwmCommand`，使用显式查表，供离线回放检查整条控制链。
文件是 `crates/robot-core/src/protocol/calibrated_chassis.rs`；它没有设备打开或发送入口。

出厂 `racecar.zip` 的普通与 one 底盘节点分别使用 1300/1200 转向系数，遥控入口另用 PWM/角度。
这些不同语义已有[源码核对记录](无人车2026资料核对.md)；不能据此获得新车的 m/s、m⁻¹ 到 PWM 关系。
本实现未复制这些系数。厂商 500–2500 µs 仅作为编码边界，另要求配置自己的电机和舵机 PWM 范围。

## 配置与行为

完整可解析示例在 [chassis-calibration-sim.json](../config/chassis-calibration-sim.json)。
**全部数字是合成测试值，1500 µs 也没有被实车验证为停车或转向中点。**
schema 1 必须明确填写 `simulation_only=true`、`measurement_status="unverified"`；不会通过更改配置声明已完成实车验证。

| 字段 | 含义与检查 |
|---|---|
| `speed_points` | `speed_mps → motor_us`；至少两个点，含精确零速度锚点，正向端点必须大于零 |
| `curvature_points` | `curvature_per_m → servo_us`；零曲率锚点两侧均须有点 |
| `motor_pwm_range` / `servo_pwm_range` | 各自的闭区间，min < max，均在协议 500–2500 µs 内 |
| `stop_motor_us` / `stop_servo_us` | Stop 对应的中性值，必须在各自范围内，并精确等于对应零锚点 |
| `reverse_policy` | `disabled` 只接受非负速度表；`calibrated_signed_speed` 必须有显式负速度表与正速度表 |

每张表的物理输入必须有限、严格递增，相邻差值也必须有限；PWM 必须沿同一方向严格递增或严格递减。
允许 PWM 整体递减以表达实际接线方向，但不会自动猜测方向。表最多 1024 点，所有字段必填，未知字段拒绝。

表内采用分段线性插值，并四舍五入到最近整数微秒；恰好半微秒时朝较大 PWM 取整。
精确标定点原样返回，区间端点可用。NaN、无穷、表外输入、非单调数据或越过配置 PWM 范围均报错；不会外推、裁剪或默默饱和。
`Drive { speed_mps: 0, curvature_per_m: 非零 }` 在预览中仍可给出转向 PWM；`Stop` 总是同时回到配置的电机与舵机中性值。

倒车时，曲率仍按车体几何转向符号解释，不自动翻转舵机方向；意图角速度是 `speed_mps × curvature_per_m`。
负速度不能通过对正速度取绝对值、照镜像生成 PWM 或复用厂商 Twist 系数实现。
显式负表只允许离线预览；实际 ESC 倒车切换若需要停顿、双击中性、制动序列或迟滞，静态查表不能表达，必须再实现对应的状态机。

## 接口和安全语义

`CalibratedChassis::new(ChassisCalibration)` 一次验证并保存不可变表；`preview(&MotionOutput)` 返回 `Result<PwmCommand, ValidationError>`。
`stop_command()` 返回配置中性帧，`config()` 只读访问配置。没有绕过校验的可变表接口。

映射错误必须交由上层明确处理为停止记录与失败状态；不能把上一个 Drive 保持为成功输出。
模块不修改 Controller 的状态、时间戳或 `StopReason`，也不会用 PWM 中性帧证明车辆已停下。
即使未来成功写入串口，也只是字节交付，仍需要设备反馈或独立测量验证停车。
当前回放是模拟时间，不能作为实时通信超时或物理制动时延验收。

## 回放入口

```bash
cargo run --locked --bin xt-stcar-robot -- replay \
  --events examples/robot-n10-replay.jsonl --config config/robot-n10-replay.json \
  --n10-config config/n10-replay.json --chassis-calibration config/chassis-calibration-sim.json
```

每条 step 增加 `chassis_preview.command` 和编码后的 `bytes`，同时标记模拟/未经测量。
总调度先检查映射再写运动记录；表外请求触发锁存急停，记录 `terminal=chassis_error`、
被拒绝的输出及中性 Stop，CLI 非零退出并保留完整终止日志。原请求仅在 `rejected_output` 中供诊断，
不会作为成功的 Drive 输出。无映射参数时维持纯物理单位的离线记录。
配置不能被 `--output` 覆盖，配置验证在产生任何运动记录之前完成。

## 真实标定仍缺的证据

出厂资料明确本车没有编码器，因此不能把 `/odom_rf2o` 或 Cartographer 估计速度当作直接轮速反馈。
取得现场条件后，应记录车辆批次、固件/ESC、轮胎与负载、电池电压、地面和测量方法，并保存原始样本。
需要用独立可靠测量核对速度/PWM、舵机中性、左/右曲率、轴距、转向行程、停车 PWM 和停止时间。
每个速度点还需检验重复性、起动死区、迟滞与正/反切换行为。

这里的单调分段线性表只表达静态、独立的速度和曲率映射。负载/电压变化、曲率随速度变化、死区、迟滞、加速度限制和动态制动都不在该模型内。
如实测不满足单调性，不应删掉异常数据以让配置通过；需要先处理测量质量或设计更合适的模型。
后续接入物理输出前仍要核对 MCU 接收校验、掉线行为、独立 watchdog、控制源仲裁和实际停车手段。
本轮不连接车辆，不读取视频。
