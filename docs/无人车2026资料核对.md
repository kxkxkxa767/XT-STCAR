## 补齐的接口

| 模块 | 资料中的具体证据 | 对 Rust 工程的作用 |
|---|---|---|
| 底盘串口 | `src/racecar_driver/src/art_racecar_driver.cpp` 与两个 node：默认 `/dev/car`，38400，8N1，电机/舵机各 uint16 小端 | 可据此编写 Rust 帧编码和串口发送模块；无需先读 MCU Flash |
| 运动消息 | 普通节点订阅 `/car_cmd_vel`；one 节点订阅 `/cmd_vel`；另有 `/teleop_cmd_vel`，均为 Twist | 三条入口语义不同，应显式适配，不能把 Twist 字段直接等同物理控制量 |
| IMU | `src/imu_get/src/publisher_imu.cpp`、`transform.hpp`：`/dev/imu`，115200，11 字节、0x55 开头，0x51/52/53 为加速度/角速度/欧拉角 | 可开发 Rust 增量解析；型号仍不能仅凭协议认定 |
| 雷达 | `Run_car*.launch.py` 加载 `lslidar_driver/lsn10_launch.py`，其 YAML 指定 N10、serial、`/dev/laser`、`/scan`、`laser_link` | 先对接该驱动或按其协议移植；不再默认先前平台教程的其他型号 |
| 相机 | `camer.launch.py`：usb_cam、320×240、yuyv、video0；另有 640×480 mjpeg2rgb 配置，YOLO 脚本默认 video20 | 已有多套输入参考，实际使用哪个设备/格式需核实 |
| 里程计 | 建图实验明确写“没有编码器”；RF2O 提供 `/odom_rf2o`，另一启动链采用 Cartographer 激光+IMU里程计 | 当前 odom 必须按估计值处理，不得作为轮速反馈 |
| 系统 | 镜像名称和烧录实验写 Bianbu 2.2；启动脚本优先 source ROS Humble | 作为出厂资料版本依据；现车系统及 GLIBC 仍待只读核验 |
| 视觉 | RedandGreen 使用 YOLOv5 ONNX，优先 SpaceMITExecutionProvider、可回退 CPU | 可参考运行库配置，不能替换 YOLO26n one-to-one 契约 |

底盘发送帧共 7 字节：

`AA motor_low motor_high servo_low servo_high checksum 55`

其中 checksum 为第 1–4 字节求和模 256（首字节索引为 0），PWM 参数单位在头文件标为微秒。
README 给出 500–2500 微秒范围，但不是新车的安全标定结果。

普通控制映射为 `motor = 1500 + linear.x * 100`，`servo = 1500 + angular.z * 1300`；
one 节点转向系数是 1200。遥控入口直接把 linear.x 当电机 PWM，并按 `2500 - angular.z * 2000 / 180` 算舵机 PWM。
因此不能把 1300/1200 系数当作经过验证的“角速度到转角”物理模型。现有 Rust 的 speed_mps/curvature_per_m 仍需轴距、转向零点、速度/PWM关系等标定后才能接入。

## 不能原样移植的行为

- 两个底盘节点没有命令超时停车定时器，也未见数值范围/NaN 校验与控制来源仲裁；串口初始化返回值未检查。Rust 应保留现有急停、超时、限值策略，并处理部分写入和 I/O 错误。发送协议没有证明 MCU 是否存在独立 watchdog 或反馈通道。
- IMU 解析按单次读取块处理，尾部不足 11 字节未跨读取保留；未见校验和检查。只要串口有数据就发布，可能混用不同更新时间的各轴量。Rust 需要增量重同步、完整帧验证和数据新鲜度管理；校验规则还需对应设备协议佐证。
- IMU 源码硬编码加速度/陀螺仪偏移；发布 `/imu_data` 的 frame 是 `imu_link`，`/IMU_data` 是 `IMU_link`，大小写不同。不能复制旧标定值或合并 frame 名称。
- 雷达 YAML 的 0.2–200 m 是过滤配置，不能当作硬件量程；Cartographer 又配置 0.15–10 m，需要一致性核对。
- Cartographer 当前配置关闭后端优化及约束采样；RPP 实验示例把 `use_collision_detection` 设为 false。不能把“包含导航程序”描述为已满足避障/回环验收。
- 教程标题“RPC”正文与插件实际上是 RPP；目录实验编号与正文编号也有不一致。实现以具体插件和源码为依据。

## 剩余缺口与下一步

压缩包未发现 STM32 命名文件、IOC、UVPROJ 或 HEX 固件工程；现阶段已有上位机发送格式，无须靠固件读取推进基础通信。
仍缺新车的准确硬件批次、MCU 接收行为/超时与反馈、IMU 型号、轴距及转向/速度标定、实际设备绑定、实机系统库版本。

Rust 后续可先完成纯离线的底盘帧编码、IMU 流解析及回归样例，再接串口与 ROS 消息；定位/导航参考该工作空间的激光里程计链路。此次仅核对资料并更新交接，未改 Rust 程序或重新部署。
