# 运动执行与通过点修正

本轮继续完善 Rust 运动控制，处理四项相互关联的问题：区分“规划出的命令”和“输出方采用的命令”、
检查速度与曲率过渡中的侧向加速度峰值、区分必停点与通过点、修正合成车辆的连续运动积分。
默认仍为 Pure Pursuit（PP），LQR 继续作为实验选项；没有增加 Python 在线控制逻辑或物理电机输出入口。

本文记录接口与实现边界。本轮完整比赛、Rust 主机检查和两程序 RISC-V 交叉链接已通过，
当前证据使用 `motion-v3-*`，本地包状态和哈希以交付报告为准。前轮[导航预测与失败首因修正](导航预测与失败首因修正.md)和
[v2 验证](motion-v2-validation.json)完整保留，不能把 v2 的 PP 55.9 秒、LQR 53.3 秒及旧二进制哈希当作本轮结果。

## 1. 执行状态由输出方推进

`SteeringEstimate` 有三个公开字段：

```text
at                           估计所属的会话单调时刻
commanded_curvature_per_m    输出方已采用的曲率目标
applied_curvature_per_m      按变化率推进得到的执行曲率估计
```

`stationary(at)` 从零曲率开始。`advance_to(now, rate)` 沿旧已采用目标推进到新时刻；
`adopt(now, command, rate, max_curvature)` 先推进旧目标，再设置新目标。
新目标不会追溯改变过去时间段。Stop 设置零曲率目标，执行曲率仍逐步回中；速度为零时不把转向回中误算成车体原地转向。
时间倒退、非有限数值、非法速度或曲率超限会被拒绝；各字段有限但差值溢出时也原子拒绝，失败不修改原估计。

这里的“执行曲率”是模型估计，依据是输出方采用过的命令及配置变化率。
它不是舵机反馈、轮角传感器或 MCU 确认，不能替代真实执行器标定。
调用者必须使用自己承诺采用的命令；将返回值丢弃却继续沿用旧物理命令，会使这份估计失去依据。

### 同步调用

`Navigator::plan_with_arrival()` 与 `plan_stop()` 只规划，调用方拿到最终输出后调用 `adopt_command()`，
或在下次规划前提供带时刻的执行估计。现有直接导航 `step*` / `stop` 作为同步包装，会采用自身返回的命令。
如果外面还有 Safety 等可能改变命令的层，应走只规划接口，不能提前采用将被覆盖的计划。

`AutonomyController::tick()` 已按此顺序工作：传感器校验 → 任务 → 导航计划 → Safety → 采用最终命令。
因此 Safety 把 Drive 改为 Stop 时，导航不能继续认为原 Drive 已执行。
同步模拟使用这条通路，输出估计与模拟车辆状态仍分别保存，不能拿模型估计冒充模拟器或实车的反馈。

### 异步 Worker

`AutonomyController::tick_with_execution_state()` 接收输出方历史，仅产生计划，不自行采用。
真实 `AutonomyWorker::spawn()` 使用此接口。输出线程定期调用 `poll(now)`，先检查原命令 lease、
结果源时刻及锁存故障，再以最终 **`ControlPoll.command`** 推进执行状态。
`ControlPoll.latest` 只供诊断，其中旧 Drive 不能绕过当前 Stop。

Worker 自己持有当前估计，用单写者的固定大小原子状态发布；提交方做一次有界读取，不等锁、不循环等待。
后台规划仍在独立线程运行，执行中一份快照、待处理一份快照；替换待处理输入时一并替换其估计副本。
采用状态不会靠后台计算完成来更新，因而没有被 poll 采用的、被替换的、因过期而丢弃的 Drive 都不计入执行历史。

`try_submit(snapshot, now)` 的时序契约如下：

1. 快照源时刻、传感器采集时刻、提交时刻和 poll 时刻必须属于同一会话单调时钟，不能用墙钟或完成时间替换源时间。
2. 提交时绑定当时可知的最新已采用状态。只有 `estimate.at <= snapshot.at` 才能沿旧目标向前推进至源时刻。
3. 若估计已晚于源时刻，返回 `SubmitStatus::ExecutionAhead`，不入队也不锁存新故障，等待更新的源快照。
   这不续租旧命令；持续没有可接受结果时，看门狗仍按原期限 Stop。不能伪造采集时戳来强行通过。
4. 原子发布或队列暂忙返回 `Busy`，由后续调度重试；`Duplicate` 不重新计算、不续租；`Stopped` 保持终止语义。
5. 同一源时刻若先提交、后 poll 才采用新命令，排队副本不会追溯更新。它表达提交时已知历史，不能承诺消除全部异步误差。

持续滞后的实车传感器输入可能频繁遇到 `ExecutionAhead`。实际适配仍需共同时间轴与有界历史关联，
不能将未来状态倒推至旧源时刻；本轮没有声称完成该适配。
规划输出最终仍受源时间 lease 检查：即使新结果看起来可用，旧已采用命令已过期时也先锁存 Stop，晚到结果不能恢复。
发生时钟倒退时，状态不回退到过去，保留原故障并将目标改为 Stop。

库保留 `spawn_with_processor()` 作为没有转向模型的旧受信任处理器钩子；
新增 `spawn_with_execution_processor()` 显式接收曲率变化率/上限，并把 `SteeringEstimate` 交给处理器。
`execution_state()` 返回输出方最新模型估计，旧无模型钩子返回 `None`。这些都是离线库接口，不是带动力 CLI。

## 2. 检查整个运动过渡的侧向加速度

普通候选的起点和目标都满足 `v²|k|` 上限，仍可能在减速尚未完成、转向已增大时出现更高峰值。
新 `MotionTransition` 同时描述速度与曲率：各自按加速/减速率或曲率变化率走向目标，到达后维持不变。

`lateral_acceleration_peak()` 在指定闭区间内检查起止点、两个渐变到达时刻及每个分段的内部驻点。
在速度和曲率都为仿射函数的分段内，`v²k` 的导数为：

```text
d(v²k)/dt = v × (2 × 加速度 × 曲率 + 曲率变化率 × 速度)
```

最后一项在分段内是仿射函数，因而只需要固定数量的极值候选；取绝对值时也检查相应峰值。
实现不靠粗采样寻找最大值，没有堆分配，输入或中间计算不合法时返回 `None`，调用者必须按失败处理。

导航检查的时域至少覆盖完整控制周期，并覆盖更长的配置预瞄时域。
即使接近目标导致普通几何 rollout 提前结束，也不能漏掉本周期稍后的过渡峰值。
超限记入 `candidates.lateral_acceleration` 并拒绝候选，不用缩短窗口或放大上限掩盖。
此检查约束的是配置模型内的正常候选；实际侧向加速度、轮胎附着与真实制动能力仍待测量。

## 3. 通过点保留顺序与首段验收

比赛任务使用 `ArrivalBehavior::Stop` 表示必须停车的目标，锥桶中间目标使用
`PassThrough { next, next_heading_rad, next_max_speed_mps }`。
通过点的含义是允许满足条件时带速度通过，不能改变必经点顺序或放宽位置验收。

导航先规划到当前必经点，再从第一段实际积分的末端位置、朝向和曲率出发规划续段。
两段不能靠拼接任意折线或修改末端位姿相连。只有经过几何与碰撞检查的续段，才能给当前速度的制动上限提供额外路程；
续段失效或无法连接时恢复停车所需的余量计算。

**当前第一段仍独立跟踪和验收。** 前视、局部进度、跟踪参考和评分都截到当前必经点；
续段不进入这些搜索，不能因为长前视看到下一个点，就切弯跳过当前点。
任务仍根据当前位姿达到原目标容差后才推进索引，再跟踪下一目标。
`next_max_speed_mps` 明确下一阶段速度上限，按可用距离和减速能力在进入验收半径前提前限速，
避免通过点一旦被验收，任务突然要求更低速度而正常制动下限还高于该值。
这限制的是候选目标速度，不承诺进入半径瞬间的测量速度必定小于下一阶段上限。
外部超速、执行器不符合模型或测量偏差仍可能使正常速度区间为空，原有 Stop 分支继续保留。

最后一个锥桶点可以预查通向灯前的续段，因此灯前禁越半平面在锥桶阶段就参与相关约束。
原有全车足迹、停稳、灯色新帧和去抖条件继续有效，任务真正进入 Finish 后才解除灯前限制。
斑马线 3 秒、普通停车 10 秒和停车位置/朝向门限不因通过点改动而放宽。

可观察的新增诊断包括 `execution_state`、`continuation_checked`、`checked_continuation_distance_m`、
`remaining_distance_m`、`goal_speed_cap_mps`、`speed_lower_mps` 和 `speed_upper_mps`。
续段距离是经过检查的可用规划路程，不是车辆已经行驶的距离。

## 4. 模拟车辆连续积分与检查

模拟车辆不再把本控制周期结束后的速度/曲率直接套用到整个周期。
`simulation.rs` 在每段命令期间让速度、曲率连续渐变，按不超过 1 ms 的子步处理，并在达到目标速度或曲率处进一步分段。
每个分段中解析积分 `速度 × 曲率` 得到航向，保留两者同时变化的交叉项；位置使用 Simpson 数值积分。
这些子步属于离线车辆模型，不改变控制器或感知器的调度周期。

起始位置与每个子步都检查车体足迹、锥桶、场地边界及当前禁越半平面。
Stop 选零速度/零曲率目标，正常结束或故障后的制动使用同一个推进函数；不能把 Stop 命令直接等同于速度已经归零。
车辆已经停稳但转向尚未回中时，继续回中也不改变位置或航向。

单元测试采用独立更细 RK4 参考和直线制动距离公式核对数值积分。
逐子步检查提高合成验证的分辨率，仍不能证明采样间绝对无碰撞，也不证明真实底盘会按相同加速度/曲率变化率响应。

### 新积分暴露的 PP 回归及修正

更准确的执行历史和车辆积分改变了原合成轨迹，开发过程中 PP 曾在灯前失败。
失败证据保留在 `docs/motion-v3-before.json`；本轮不把中途结果改写成“始终通过”。除通过点的下一阶段限速外，
根据复现还修正了缓存末端路径和带朝向评分：

- 缓存路径没有碰撞，不代表从偏离后的当前姿态仍能到达末端。有显式目标朝向时，局部参考横向距离超过
  `goal_tolerance_m × 0.5` 就提前丢弃缓存并重规划；这是更早纠偏，不是增大到达容差。
- 原带朝向 rollout 用位置距离与 `|航向误差| / 最大曲率` 组合评分，可能过早把车头摆正而留下横向偏差。
  新评分把每个预测姿态与参考姿态对应的四个车身角都变换到世界坐标，取对应角距离最大值，再沿预测弧长累计。
  位移和转角体现为同一个米制车体位姿误差。这个度量改变了位置与朝向在评分中的相对影响，
  不能称为共用控制评分的权重完全未变；未调整的是 LQR 的 q/R 参数和比赛门限。

普通无朝向通过点仍按其首段追踪点评分，PP 默认和 LQR q/R 未改；控制周期、到达容差、灯前验收及普通停车期限保持。
保持单个候选曲率目标的预览无法表达所有未来转向策略，候选失败不等于所有策略都不可行，单场完成也不证明一般收敛。

## 验证与交付边界

本轮 Rust 常规测试 266 项通过、0 失败，1 项原生 ORT opt-in 测试按默认忽略；跟踪 example 2 项、Python 交付 34 项通过。
fmt、all-targets clippy `-D warnings` 和两个 RISC-V 交叉链接通过。
其中 Worker 专项 14 项、通过点专项 4 项已有回归覆盖，未把忽略项或前轮模型测试计入通过数量。
汇总见[验证报告](motion-v3-validation.json)，构建见[构建报告](motion-v3-build.json)。
本地包的生成/核验状态、路径与哈希以 `motion-v3-delivery.json` 为准；交叉链接通过不等于包已核验。

所有新状态、队列和逐子步计算留在内存，没有新增每 tick 或每子步磁盘写入。
原有最多 17 帧首次异常窗口、结束摘要和可选有界 trace 保持；eMMC 5.1 的擦写优化不降低感知/控制频率，
也不因可选日志额度触发 Fault。必要诊断照常保存。

仍按“暂不接车”执行：没有 SSH、真实相机/串口/电机操作，没有 RISC-V 目标执行或车端 libc 替换。
本地交叉链接目标保持 `riscv64gc-unknown-linux-gnu.2.38`。工具链、环境、模型和本地 `dist/` 包不进 Git，
源码按[上传规范](../上传规范.md)直接提交 main；用户规则 PDF 保持原件且不暂存。视频和暂停的 STM32 固件任务均不涉及。

真实速度/转向反馈、时间同步与扫描去畸变、传感器融合、低速 PP/LQR 切换滞回、规划器原生曲率采样和物理 MotionSink 仍待后续。
