# 采用约束与前向恢复

本轮将异步输出的采用约束前置到候选选择，并补齐停住后的有限前向恢复。默认仍为 Pure Pursuit，LQR 仍属实验；未调整 LQR 的 Q/R、车体尺寸、障碍余量、任务容差、普通停车期限或感知与控制频率。最终执行依据仍是 `ControlPoll.command`。

问题来自 v6 完整异步运行保存的真实软件输入。源时刻 16800 ms、规划时刻 16860 ms 的 LQR 计划，停车包络使用的历史上界已达到 `V=0.3 m/s、K=2 m⁻¹`。停车矩形在源车体系的范围为 `x=[-0.311993913, 0.531993913] m、y=±0.294393913 m`；零基索引 331 的激光障碍圆盘余量为 **−0.004311433629389386 m**。独立复算完整 360 束扫描与当前 Rust fixture 都复现了该拒绝。它说明保守包络与障碍相交，不等于车体已经碰撞；第一张拒绝也不是后来整场失败的唯一充分解释。原始证据见 [v6 失败复核](motion-v6-async-failure-review.json)。

上传复核包中的 **246 组是速度/曲率算术探针组合**：它们满足绝对速度和曲率上限，并非全部满足该拍加减速、转向变化率等条件；既不是真实导航候选数量，也不是 246 次完整 Rust 认证。该更大集合的包络均不变，因此其合法候选子集也不能靠本帧换低速缩小包络。把历史上界整体改低属于反事实，不能当成本帧可采用的修法。

采用证书由 `Option` 改为 `Result<AdoptionCertificate, CertificateFailure>`。检查仍按原顺序早退，正常路径不枚举全部失败；非法数值、源时间不一致、lease/采用窗、速度区间、转向 slew、侧向加速度、地图、激光、视觉锥桶和灯前边界有不同原因码。诊断字段包括：

- `reason`、`constraint_index`、`signed_margin`、`margin_unit`：首个失败原因、零基障碍/角点索引、带单位余量；不存在或非有限的余量留空。圆盘相切仍拒绝。
- `source_at`、`pose_at`、`oldest_sensor_at`、`planned_at`、`max_age_ms`、`lease_expires_at`、`adoption_through`：原源时刻及实际有效期，采用窗起点为 `planned_at`。
- `historical_speed_bound_mps`、`historical_curvature_bound_per_m`：已经发生的历史上界；`speed_bound_mps`、`curvature_bound_per_m` 和 `stopping_rectangle_body_m` 在检查走到几何阶段后填入。

这些字段随计划观察结果和显式异步验证报告传播，不更改命令选择，不新增默认逐拍落盘。新增导航/阶段诊断采用稀疏 JSON：全默认工作对象与 None 省略，缺失表示对应 Rust 默认值（零工作、未搜索、无约束/失败）；非默认对象全部字段完整保留。主机计时仍须显式开启，逻辑时间不依赖墙钟；保留未采用计划的诊断不等于采用该计划。

`AdoptionConstraints` 使用最旧源时间与 `runtime.max_command_age_ms` 推导实际 lease 和采用窗，不能从默认配置另造一个期限。当前候选继续保留源到规划时刻的历史 V/K、当前投影和已持有目标；换低目标不删除历史，同源不续租。规划器先检查同一停车矩形，使明显不能采用的候选提前退出，最终证书再检查完整原输入、历史、时间及几何，输出端还核对真实采用前提。

减速前瞻检查采用窗起点、中点、终点 **3 个固定延迟情形**，窗宽为零时只检查一次；每个情形按其固定延迟推演后续命令。新源采集相位保留当前源年龄，未来处理延迟以本次观察到的源年龄建模；后续目标按正常减速度逐步降低，保持转向目标，每份预测新源保留其采集后经历的已持有目标上界。新源的历史从新采集状态开始，不是把旧源历史清零。预测最多 64 个规划时刻、2 秒，且末端必须在模型中停稳；额度不足直接拒绝，不截短后冒充完整刹停。

这能排除“当前能采用，但若继续向前就来不及在后续源上正常减速”的已复现局部陷阱。**有限 3 时刻、多源后备减速前瞻不是整个采用窗、任意逐拍延迟组合或所有未来策略的递归可行性证明**，也不预测尚未观察到的新障碍。真实新源、最终连续采用窗证书和输出端校验仍不可省略。`admission_forecast_work` 区分情形数、源检查数、投影调用与预扣毫秒区间；这些不是 CPU 指令数或目标板耗时。

恢复仍优先使用普通网格和前向搜索。普通前向队列以 `OpenEmpty` 结束、且没有已经成功的普通路线时，才在原剩余额度内尝试连续几何；预算耗尽不触发加额放行。`OpenEmpty` 只表示这次有限搜索没有结果，不能写成物理上无路。

连续恢复保留完整车体外接圆和原 clearance，再预留停稳后最小正常起步候选的停车距离，用障碍圆盘、地图矩形和灯前半平面直接检查胶囊，替代网格半格对角线带来的额外量化膨胀。每个运动小段用**真实模型弧长** `L`，其曲率上界为 `K` 时，中心轨迹到端点连线的偏离不超过 `K L²/8`；胶囊半径再加累计位置误差。不能用端点弦长代替弧长，也不能只检查离散端点。

完整测试曾暴露一个中间版本回归：既有双锥场景在仍以 0.2 m/s 行驶时过早进入恢复，后来被带到距第二锥桶仅剩 `1.067410 mm` 静态圆盘余量的位置。该配置停稳后最小正速度候选为 `.01 m/s`，原停车门要求 `1.083333 mm`，因此全部 44 个候选被拒绝；这是恢复与正常运动衔接的问题，不是无碰撞就能继续开。最终在连续域增加 `v_restart=.5×min(v_max,a×T)` 对应的 `2Tv_restart+v_restart²/(2b)` 预留。50 ms 和 100 ms 配置分别为 1.083333 mm、4.333333 mm；原实际制动门不变。新增第 8 项回归固定该陷阱，既有双锥测试也重新通过。对照实验显示，额外限定“首次恢复必须停稳”并非该修复所需，且改变完整异步 LQR 路线后导致 79.263 秒停滞；已撤去此限制，保留直接针对起步空间的预留。这个局部预留不构成任意运动状态的递归可行性证明。

旧的“端点曲率平均值 × 路程”会漏掉小段中途达到转向目标的时刻；速度和曲率同时渐变时，还会漏掉二者交叉项。新 helper 按速度、转向各自到达时刻拆成最多 3 个仿射段，解析积分朝向与路程，每段固定 4 个位置积分子区间。对局部速度/曲率上界 `V/K`、加速度 `a` 和曲率变化率 `r`，位置中点积分的每段余项为：

`(3|a|VK + V²|r| + V³K²) × h³/24`。

误差逐段相加，并把已有朝向误差造成的后续位移加入位置上界。最多 12 个子区间是固定工作量；精度依据是导数余项，不是“采样更密所以安全”。另计显式浮点舍入余量；这里是给定初态和渐变模型的数学界，不声称机器验证的区间算术或真实执行器误差界。普通模式保留原积分数值路径。

独立 `.4 m` 基元反例中，旧末端位置误差约 `0.335292 mm`，已超过当时胶囊弓高扩张 `0.15625 mm`；一个新插入的障碍被旧胶囊放行，而真实模型末端违反原车体余量约 `0.005 mm`。新实现及镜像均拒绝该障碍，积分误差落在累计界内。同步速度/曲率渐变另与两种分辨率的独立积分对照；这不是实车碰撞记录。

误差随 `CarNode`、终端两段连接、`PassThrough` 续段和候选下一拍终端检查传播。缓存续段重验保存的最大采样弧长及累计位置界，不能恢复成零误差折线。每拍从新观测重建几何，沿途新障碍和当前灯前边界仍会拒绝旧路线；目标、朝向或边界变化按原流程清理恢复状态。参考路径只是跟踪参考，实际命令仍从新源重新规划和认证。

灯前 fixture 还暴露了一个独立遗漏：真实积分末端已进入原位置/朝向容差，但目标中心在车后，旧连接入口仍要求向前接回中心。恢复搜索现在允许这个**真实末端加上误差界后仍在原容差内**的节点结束，不改容差、不把末端坐标或朝向改写成目标值。

普通搜索、恢复和后续路段共享 `max_grid_cells` 节点账本；`allocated_nodes` 包括各次搜索的初始节点，`generated_nodes` 和 `expanded_nodes` 分别报告生成与展开，不能混用。整次导航仍共享原 256 次求解、1024 次迭代、65536 份终端预扣样本额度。单次迭代用尽、整拍终端额度不足、节点额度不足和普通队列为空分别报告；已有完整认证结果可以使用，额度不足不会把未认证候选变成可行。
