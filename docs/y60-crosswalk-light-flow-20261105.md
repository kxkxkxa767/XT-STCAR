# y60 斑马线速度锚定与灯前连续控制

基线为实车y59／166。用户观察斑马线停得太远、灯前反复停走，依“分析确认后直接修复”的要求继续处理，候选y60／167。

## y59 实跑证据

起步至终点31.260 s，扣等灯10.385 s为20.876 s（历史保存帧口径）。斑马线前停距0.687 m，灯前停车事件前距0.599 m、终点0.171 m，质量等待计数为空，已锁车，92个文件完整取回。

斑马线静止定位与y58第二轮仅差约1.8 cm，不能解释多停53.1 cm。按原标定投影，y59起跑前静止纵向加速度均值为+0.1575 m/s²，y58第二轮约+0.0014；静止相机俯仰约相差1°，与重力投影变化的量级一致。第27帧长积分速度已使1570提前降1550，28帧在距线1.801 m处收油；雷达锚定速度约1.071，旧静止点长积分却为1.270 m/s。偏高速度还让滑行中的补推预算不通过，48帧在0.687 m处进入原有3秒等待。此轮灯区改动没有改变斑马线源码或电机输出权限，未发现跨段逻辑串用。

灯前可见时序为1550→1500→1550（滚动补推）→1500→1550（车尾进区）→1500→连续1300。灯刹本身只有一段，红帧未打断，也没有质量或ACK故障；终点另一次1300状态独立。首次保存收油时还没有修正当前速度，只能用raw1.408 m/s；收油后预测会停在门架前约1.46–1.49 m，但旧恢复门槛仍让它继续滑至低速才补油。问题是继续用长滑行停车预算，而后段已经具备主动刹车。灯区事件总用时约3.495 s，并不比y57的3.592 s更慢；用户指出的是连贯性。

停车后37帧红灯持续可见。第94张图可清楚看到绿色灯亮，连续检测分数0.3556、0.3018，未达到旧0.5门槛，仍走了10.5秒兜底。

## 改动

斑马线接近阶段使用已算出的近期雷达锚定车速，加短时IMU变化和剩余电调响应量。它已经补偿雷达坡度滞后，因此不再与带长积分偏差的速度取最大值；近期锚点不可用时仍退回原雷达路径。静止相机定位、等待3秒、斑马线后第一桶控制和两桶转向不改。日志新增相应 `speed_basis`。

灯前保持原1550，直到“再推一帧＋完整电调尾推＋刹车起效＋强刹距离”将用尽0.55 m目标的空间，才切一次中位，接原独立1300。删除正常过程中的滚动补推和车尾进区补推两种状态；正常线路为保持→收油→一次刹车。未过光电或者灯一直未亮且达到原等待时机时，保留原有继续通过处理，不会因为硬件不触发而永久等候；不再仅凭车尾差几毫米就恢复推力。单次刹车及终点状态不改。

已经见过红灯后的比赛等待阶段，绿灯阈值对齐检测器既有发布阈值0.25；仍须两帧新鲜连续绿灯且两帧均无红。没有见过红灯的情况及Python参考行为仍用0.5。新放行证据记录实际阈值。

## 验证与下一步

只运行既有检查，不新增场景仿真或测试文件。固定实车输入显示第28帧新速度约1.071 m/s，旧为1.270；改变给油后真实后续速度会不同，不能把这个差值当成已测得的新停距。
