# 机器人模块：离线语义、安全策略与回放

`crates/robot-core` 是纯 Rust 库 `xt-stcar-robot-core`，提供传感器语义校验、确定性安全状态机及
离线输出接口。`crates/runner` 负责 JSONL 事件回放和日志调度。核心库中没有 SSH、ROS、相机、串口、
GPIO、PWM 或电机驱动，不会自行发送底盘命令。

## 模块边界

| 模块 | 已实现内容 | 真实接入前仍需的依据 |
|---|---|---|
| 传感器数据 | IMU、雷达、里程计、视觉摘要的强类型数据与语义校验 | 真实设备型号、数据格式、时间来源与驱动 |
| 安全策略 | Disarmed / Armed / Running / Fault，急停锁存、deadman、心跳/指令/帧过期、限幅拒绝 | 现场风险评估、控制周期、停车距离、物理急停和硬件看门狗 |
| 底盘输出边界 | `MotionSink` trait 与只记录到 Vec 的 `RecordingSink` | 底盘转向结构、协议、速度/转角语义、可靠停止确认 |
| 调度与日志 | runner 按显式事件时间调用 Controller，记录输出 | 传感器时钟同步、实际消息队列和服务生命周期 |
| 视觉衔接 | VisionSample 含时间、frame、图像尺寸与检测数量 | 标定、真实模型结果与车端 ONNX Runtime 兼容性 |

这些模块实现了软件内的离线接口与策略，不能称为已实现真实传感器驱动、ROS 节点、定位融合、
路径规划、障碍物避让或底盘控制。激光距离和像素框不会自动生成运动意图；不由像素框估算真实距离。

## 时间、单位和 frame

`Timestamp(u64)` 的 JSON 表示是整数，单位为**本次回放/会话开始后的单调毫秒**，不是 Unix 时间。
事件到达时间是 `TimedEvent.at`，采样时间是每个样本的 `captured_at`。时间倒退、未来采样、
同一传感器采样倒序与过期帧会停止并进入 Fault；重复帧不会刷新采样时间。

IMU 加速度为 m/s²、角速度为 rad/s；里程计位置为 m、线速度为 m/s、角速度为 rad/s。
姿态显式使用归一化四元数 x/y/z/w，拒绝非有限值和近零/非单位四元数，不悄悄归一化。
雷达角为 rad、距离为 m，`ranges_m` 中的 `null` 明确表示无返回/未知，不按零距离处理。
视觉摘要只有像素尺寸与检测数量；细粒度检测框由视觉模块及 runner 的推理日志保留。

每类传感器的期望 frame 与里程计 child frame 在配置中显式指定。遇到不匹配 frame 会拒绝，
不假定相机、雷达、IMU 和车体坐标一致，不伪造 TF 或外参。IMU 是否含重力以及真实坐标轴约定
仍由将来的适配器明确；样例的 9.81 仅用于展示数据格式。

## 状态与停止规则

初始状态 Disarmed。显式 Heartbeat、Deadman pressed、所需的新鲜传感器样本齐备后，Arm 可进入
Armed；Armed 的输出仍是 Stop。还需在 Armed 接收有效 Motion，再显式 Start 才进入 Running。
Motion 仅表达内部抽象 `speed_mps + curvature_per_m`，不推导实际舵机角、差速轮速或串口字节。

Running/Armed 在处理任何新事件前，先以该事件时间检查旧观测是否已经超时。
因此迟到的心跳、指令或传感器事件不能覆盖已发生的超时再继续 Drive；不依赖调用者刚好先发 Tick。
超时边界使用 `age >= timeout`；超过速度/曲率限制直接 Stop/Fault，不夹紧后继续运动。
非有限指令、deadman 松开/过期、心跳缺失/过期、指令缺失/过期、必需传感器缺失/过期均阻止运行。

EmergencyStop 锁存 Fault 和急停标记。Heartbeat、Motion、Arm、Start、Disarm 都不能清除该锁存。
只有在显式 Deadman pressed=false 后 ResetFault 才回到 Disarmed；Disarm 不冒充 deadman 物理释放。
Reset 丢弃旧命令、心跳和传感器
新鲜度，必须重新准备数据、Arm、Motion、Start。Fault 从不自动恢复为 Running。

Controller 只计算 `StepReport` 和 `OutputRecord`。调用者将记录交给 `MotionSink::emit`；本工程
只提供内存记录和日志实现。trait 的存在不证明真实设备能够停止；将来物理适配器还必须具有独立
通信超时停止、错误反馈与现场验证，本轮没有该适配器。

## 模拟配置和确定性样例

`config/robot-sim.json` 要求 `simulation_only=true`，所有限值、超时、frame 和必需传感器均显式写入。
0.2 m/s、0.5 m⁻¹、150/200/250/500 ms 只是保守的离线演示参数，**不是车端标定值或安全保证**。

`examples/robot-sim.jsonl` 先准备三个合成传感器样本，显式启用内部运动意图，再在指令到期时发送
迟到的 Heartbeat。该事件应得到 Stop/Fault；后续 Motion 不会自动恢复。样例最后演示 Reset 与急停锁存。
样例无需模型或 ONNX Runtime 即可回放，不访问任何硬件。

公开入口为 `Controller::new(SafetyConfig)`、`handle(TimedEvent)`、`tick(Timestamp)`。
`RecordingSink::records()` 可借用记录列表，`into_records()` 可取出全部离线记录。
相关测试覆盖确定性回放、启用顺序、超时边界、迟到消息、急停恢复、时间倒退、非有限/越限指令、
缺失传感器、frame/四元数/雷达值校验及模拟配置约束。

## 可运行的总调度程序

工程根目录执行（不需要模型或推理库）：

```bash
cargo run --locked --bin xt-stcar-robot -- replay --events examples/robot-sim.jsonl
# 日志写入文件：
mkdir -p work
cargo run --locked --bin xt-stcar-robot -- replay \
  --events examples/robot-sim.jsonl --output work/robot-replay.jsonl
```

样例含 17 个输入事件；runner 自动追加结束 Stop，因此输出 18 条运动记录：2 Drive、16 Stop，
最终 Disarmed。`Drive` 只是日志中的内部运动意图，所有记录均含 `physical_output_enabled=false`。
输入/输出有大小限制，未知字段、时间倒退、重复图像序号会明确失败。
输出先完整生成，再通过同目录临时文件原子替换；无效输入不会截断已有日志或硬链接指向的输入文件。

JSONL 还支持真实图像帧事件，路径相对于事件文件目录：

```json
{"at":20,"event":{"type":"vision_frame","path":"frame.png","sequence":1,"frame_id":"sim_camera"}}
```

与普通事件按 `at` 排序合并，`sequence` 严格递增，frame 必须符合显式配置。
带真实帧的回放需要模型、相邻 provenance 和本机架构的标准 ORT C 库：

```bash
cargo run --locked --bin xt-stcar-robot -- replay --events path/to/with-images.jsonl \
  --model models/yolo26n.onnx \
  --runtime-lib toolchains/onnxruntime-macos-arm64-1.29.0/lib/libonnxruntime.1.29.0.dylib \
  --output work/robot-vision.jsonl
```

同一个 Session 服务所有图像，检测详细结果进入 `vision` 日志，摘要送入传感器校验。
解码/推理错误会记录完整的急停锁存 Stop 并非零退出；日志超限/损坏不覆盖先前完整日志。
没有 `vision_frame` 时不加载推理库。
本机已验证 19 个输入事件（含 2 张相同真实样例）：两帧各 5 个检测、结果一致、
20 条运动记录（4 Drive / 16 Stop）且最终 Disarmed；另验证损坏图片触发急停。
原始证据见 [整链路验证](robot-reference-validation-2026-09-07.json)。
事件时间是模拟时钟，回放不是实时控制循环，不能据此承诺硬件停车时限。

## 2026-09-08 扩展入口

总调度新增 `n10_bytes` / `--n10-config`、`--chassis-calibration` 与独立的 `serial-capture`。
回放/底盘预览仍不操作硬件；采集默认计划，仅显式 `--execute` 才打开传感器端口。
`crates/device-io` 负责串口，`robot-core` 仍是无 I/O 的纯逻辑；没有物理 MotionSink。
N10 每包16束只更新接收健康，不代替全圈扫描或避障。多样本解码批次每块只记录一次，
后续 step 使用 `imu_sample_index` / `n10_packet_index` 指向该批次。
详见 [N10 协议](N10协议依据.md)、[底盘标定映射](底盘标定映射.md) 和 [串口采集](Rust串口采集.md)。
