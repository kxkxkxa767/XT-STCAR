## N10 普通单回波包

字节偏移从 0 开始。不要与 108 字节 N10_P 或 M10 系列混用。

| 字节 | 含义 | 源码依据 |
|---|---|---|
| 0–1 | 固定 `A5 5A` | `.cc:478–501` 的 `receive_data` |
| 2 | 包长，当前 N10 为 58（`3A`） | `.cc:172–182` 与 `:517–518` |
| 3–4 | 本解析器保留原值，不赋予转速/时间含义 | N10 分支未解释这两个字节 |
| 5–6 | 起始角，uint16 **大端**，单位 0.01 度 | `.cc:176`、`:579–582` |
| 7–54 | 16 个固定槽位，每槽 3 字节 | `.cc:174–175`、`:605–606`、`:649–660` |
| 每槽前 2 字节 | 距离 uint16 **大端**，毫米；`FFFF` 为无效回波 | `.cc:617–623`、`:649–660` |
| 每槽第 3 字节 | 原始强度 uint8，无物理单位声明 | `.cc:653`、`:660` |
| 55–56 | 结束角，uint16 大端，单位 0.01 度 | `.cc:177`、`:586–596` |
| 57 | 前 57 字节求和模 256 | `.cc:536–553` |

厂商函数名 `N10_CalCRC8` 实际实现为逐字节加和后 `& 0xff`，不是多项式 CRC。
N10 配置指定 230400 波特（`.cc:178`）；串口类以 8N1 初始化（`src/lsiosr.cpp:322`）。
本解析模块只处理数据流，没有串口打开、配置或雷达启停命令。独立的
[串口采集模块](Rust串口采集.md) 提供显式传感器读取；没有发送雷达启停命令。

距离原值始终保留；0、FFFF 和配置范围之外的值转换为 `None`。边界内距离为米，强度单独保留。
YAML 中 0.2–200 m 是过滤设置，不是 N10 硬件量程；Rust 的最小/最大距离必须显式配置，
不能把合成回放参数视为实车标定。

## 修正与有意保留的限制

厂商按有效点数量计算角度插值分母，然后仍用原始槽位索引 `num` 插值（`.cc:617–673`）。
有坏点时，后续有效点因此偏离原来的位置。Rust 保留全部 16 个槽位并始终除以 15，
首尾槽分别对应起止角；坏点只是 `None`，不会挤掉角度位置。
这延续厂商全有效包的插值结果，是对固定 16 槽格式的明确修正；尚无实车原始包对照。

角度原值超过 36000 的包拒绝。跨零的正向 wire 角跨度用一圈内差值计算；
`packet_sample()` 采用厂商 `x=r*cos(a), y=-r*sin(a)`（`.cc:1138–1139`）的方向，
因此输出角度增量为负。跨零时连续展开角度，避免在一个局部样本内部制造跳变。
激光 frame 到车体 frame 的安装位置、朝向仍需要现场外参，不能把它直接当作车体坐标。

厂商可能把包长直接用作读取长度，又按固定 PACKET_SIZE 校验（`.cc:517–538`）。
Rust 固定只接受 58 字节 N10 包；一次 feed 最多 4096 字节，内部最多保留一个未完成包。
错误长度、噪声、错误校验或角度异常均逐字节重新同步，可保留错误数据中后续出现的有效包头。

N10 分支关闭 GPS 时间（`.cc:180`），原始包没有在所读源码中得到确认的测量时钟字段。
Rust 保留 `first_received_at`、`received_at` 两个主机单调接收时刻，局部样本以首字节接收时刻为
`captured_at`，不会用后续字节/重新发表时刻刷新旧数据。未完成包达到配置的最大年龄即丢弃，
空 feed 同样推进过期检查；接收时间倒退和超大输入在修改状态前拒绝。
这仍是接收时间近似，没有声称测量时间同步、逐束采样间隔或运动去畸变。

**每包仅有 16 束局部数据，不是完整一圈。** `N10DecodeBatch` 总会保留校验通过的原始包；
`packet_sample()` 在全部回波未知或角跨度为零时返回 `None`，不把不可用包作为新鲜传感器样本。
可用局部包的传感器更新仅表明接收健康，不能证明前方/全周覆盖、无障碍或避障有效性。
本轮不实现整圈拼接、角覆盖验收、丢包检测、ROS 发布或定位。

## API 与验证

`N10Config` 必填 `frame_id`、`range_min_m`、`range_max_m`、`max_packet_age_ms`；
`N10Decoder::new` 验证配置，`feed(bytes, at)` 输出原始包及校验、长度、角度、过期、丢弃统计。
`N10Packet::packet_sample()` 只提供 16 束局部 `LidarSample` 转换；原始距离和强度仍在 packet 中。

测试采用注明为合成的固定 58 字节向量，起始 350°、结束 5°、16 个 1.0–2.5 m 的回波。
覆盖大端与单位、跨零与方向、所有分包边界、粘包、噪声/内嵌包头重同步、错误长度/校验、
坏点保位与全未知抑制、异常角度、过期边界/空 tick、时间倒退/输入限制不破坏状态、
持续噪声的缓存上限及严格配置。不使用厂商可执行程序生成期望值，不把合成测试称为硬件验收。

本机 `cargo test --locked -p xt-stcar-robot-core --test n10` 已通过 8 项测试。

## 合成回放夹具

`config/n10-replay.json` 显式使用 `laser_link`、0.02–12 m 过滤范围和 50 ms 未完成包年龄上限。
`config/robot-n10-replay.json` 为 `simulation_only=true`，仅把 lidar 列入必需传感器，
传感器超时设为 80 ms。它们用于独立检查 N10 接收链路，**不是实车传感器配置或安全标定**。

`examples/robot-n10-replay.jsonl` 的十条记录全部人工合成，和设备采集数据、视频内容无关。
有效包采用上面的固定测试向量：350°→5°、1.0–2.5 m，保留两个任意的未解释 header 字节；
错误包只翻转末字节校验的一位，不把传感器时间更新为其到达时刻。

| 时刻（ms） | 事件与预期行为 |
|---|---|
| 0 | 有效包前 12 字节，尚无传感器样本 |
| 5 | 剩余 46 字节；生成一个 16 束局部样本，`captured_at=0` |
| 5 | heartbeat、deadman、arm、motion、start，记录模拟 Drive |
| 40 | 错误校验包；记录校验错误，不刷新 lidar 的接收样本时间 |
| 79 | Tick；有效样本年龄尚未达到 80 ms |
| 80 | Tick；触发 lidar 超时，Fault 并记录 Stop |

事件类型为 `n10_bytes`，只允许 `type`、`bytes` 两个事件字段，字节数组必须为 1–4096 个 uint8；
外层只允许 `at`、`event`，时刻单调不倒退。空数组、未知字段、越界字节和过大输入均应拒绝。
零输入过期推进由普通 Tick 负责安全超时；增量解析器自身也支持空 feed 检查未完成包年龄。
