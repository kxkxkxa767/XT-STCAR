# 导航预测与失败首因修正

本轮根据用户提供的[第二份修改意见](https://chatgpt.com/share/6aa27143-7204-83ee-ad9a-7067ef49a1bc)，
核对 Rust 导航的候选预测、路径末端连接、评分参考及失败诊断。分享中的判断作为待核验建议，
实际取舍以当前源码和独立复现为依据。前轮设计与结果保留在[运动控制设计与对比](运动控制设计与对比.md)，
不覆盖历史证据。

当前仍默认 Pure Pursuit（PP），LQR 保留为实验选项；两者共用路径规划、候选可行性检查和 Safety 通路。
新功能使用 Rust，没有新增在线 Python 进程、控制器算法依赖或物理运动输出入口。
本轮实际测试和构建记录见[验证汇总](motion-v2-validation.json)，整场逐算法摘要见[比赛对比](motion-v2-competition-comparison.json)。

## 修改依据和范围

| 核对项 | 问题及本轮处理 |
|---|---|
| 候选速度预测 | 原正常预测使用 `max(当前速度, 候选目标速度)`，减速候选可能得到相同轨迹；正常预测改为受加减速约束的速度过渡，紧急停车检查单独保留保守速度 |
| 曲率过渡 | 正常预测从上次已选指令曲率开始，按曲率变化率走向候选值；这仍是执行器模型假设，不是实测转向反馈 |
| 路径末端连接 | 瞬时定曲率圆弧只可用于初始猜测；验收使用实际渐变曲率积分所得的轨迹、末端位姿和碰撞检查，不把最后一点直接改成目标 |
| PP/LQR 共用评分 | 对灯前/终点等有朝向的目标，累计预测整段的位置与航向误差；无朝向的中间点保留追踪点评分；按目标要求选择，与算法名称无关 |
| 灯前禁越线 | 任务与导航共用有向半平面，约束全局搜索、局部扫掠及停车圆盘；不能先越线再绕回合法目标 |
| 首次异常诊断 | 记录路径版本、进度、请求/限速/选中曲率和候选拒绝计数，模拟摘要保留第一个异常前后的有界窗口 |
| 后续建议 | 低速切换滞回、规划器原生参考曲率样本、真实传感器同步及反馈仍属后续工作，不因新增诊断而视为已完成 |

本轮不以增大比赛停车期限、放松目标朝向/足迹容差或绕过碰撞检查换取通过。
算法比较也不自动改变默认配置；即使实验配置完成某个合成场景，也不能据此认定其优于 PP。

## 正常预测与紧急停车分别计算

实现位于 `crates/robot-core/src/navigation.rs` 的 `rollout()`。
输入分别保存当前测量速度、候选目标速度、上次指令曲率和候选曲率。
普通运动预测在 `preview_horizon_s` 内，按配置的加速度/减速度及曲率变化率推进；
达到候选值后维持该值。每一步的速度积分覆盖渐变段与剩余匀速段，曲率采用该小步的时间平均值。

例如当前速度为 0.30 m/s 时，0.30 m/s 与 0.24 m/s 两个目标必须产生不同的正常预测，
这样评分才有依据判断减速带来的轨迹变化。不能把 0.24 m/s 直接当作当前速度来预测，也不能用
0.30 m/s 贯穿所有正常候选而抹去减速的作用。

紧急停车检查仍使用：

```text
v_env = max(当前测量速度, 候选目标速度, 0)
d_env = 2 × v_env × 控制周期 + v_env² / (2 × 配置减速度)
```

`d_env` 覆盖一个已接纳命令周期、反应周期和制动距离。以它扩展的车体可达圆盘继续检查障碍物与场地边界，
覆盖转向回中期间的中间轨迹。正常预瞄因临近目标而缩短、或者候选目标速度较低，都不能把这个圆盘缩小到
当前速度所需的停车范围以下。此保证依赖真实制动能力至少达到配置假设，仍需接车后测量。

普通预测每步不超过一个控制周期，并受网格分辨率、净空和空间步长限制；循环最多 1024 步。
网格跨格检查及车体足迹检查继续执行，渐变曲率下使用额外的步间扫掠余量。
超过采样预算时拒绝候选，不把尚未检查的剩余轨迹当作安全。
这些界限限制内存和迭代数量，但不能替代 RISC-V 目标上的最坏执行时间测量。

## 末端位置和朝向必须来自真实积分

全局车模型搜索的普通边使用 `car_primitive()`，从父节点曲率逐步转向目标曲率。
短距离终端连接也必须沿用这个约束：瞬时定曲率圆弧可以帮助寻找初值，但不能直接成为已验收的路径。
连接失败时继续有界搜索或返回无可行路径，不能通过移动末端点、补一条未检查直线或原地旋转来连接目标。

验收同时看积分得到的实际末端位置、要求的目标朝向、最大曲率、曲率变化率和沿途网格碰撞。
有目标朝向的停车任务尤其需要保留朝向约束；仅到达位置容差并不等于灯前或终点停车合格。
单段连接最多 8 次端点修正，同时调整目标曲率和弧长。另在开始搜索时，对前方且距离不超过
`min(2×lookahead, 2m)` 的有朝向目标尝试一次双段连接：两段等长，优化两个目标曲率及总弧长，
最多 8 次有限差分修正；每段仍执行同一个 `car_primitive()`。矩阵退化、超限或碰撞即放弃尝试。
连接验收的位置误差小于 `min(goal_tolerance/4, 0.1mm)`，朝向沿用原有半容差，不移动真实末点。
回归中的同朝向小横移原先被离散搜索绕成 4.228m 环，现在得到不足 1m 的 S 形路线；
测试独立反算段曲率/变化率，并覆盖障碍与后方目标拒绝。这不是最短路径保证。

## 按目标要求评分，检查整段接近过程

复现发现：只比较 2 秒预测终点会漏掉中途弯道误差。PP 在灯前接近过程中已有约 10cm 偏离，
到末端时可用距离不足以同时修正位置与朝向；再增加末端朝向惩罚会留下横向误差。
本轮因此只对有显式朝向要求的目标使用整段参考误差。纯位置中间点仍采用原追踪点几何，
没有把未通过全阶段回归的评分试验写入默认通路。

在现有 rollout 积分及安全检查循环中，每个通过检查的小步按实际预测弧长取参考点：

```text
s_i = 当前位姿的局部参考弧长 + 累计预测行程
E = Σ Δs_i × (位置距离_i + |wrap(预测yaw_i - 参考yaw_i)| / 最大曲率) / Σ Δs_i
J_heading = E + 0.5 × (候选速度 × 控制周期)²
                × (|候选曲率 - 跟踪请求| + |候选曲率 - 上次指令|) - 0.3 × 候选速度
```

距预测终点仅余目标位置容差时，参考朝向采用任务指定值。曲率偏好的系数取一拍横向位移的量级，
避免固定曲率偏好压过实际路径误差；它是评分尺度，不是执行器误差保证。旧速度奖励保持。
全部几何误差在原循环中累计，不重复运行一套预测。参考游标只向前访问路径段，无额外路径分配。

无朝向目标令 `a=min(剩余距离/lookahead,1)`，评分为预测端点到追踪目标的距离，
加 `0.15a²×|候选曲率−请求| + 0.08a²×|候选曲率−上次指令| − 0.3×候选速度`。
接近终点时曲率偏好随剩余距离平方衰减，避免短行程下几何收益变小而旧偏好仍占主导。
两种跟踪器使用同样的目标类型分支；默认 PP、LQR 参数及输入误差域均未修改。

## 灯前边界同时进入任务判断和导航

`robot-core/src/autonomy.rs` 的 `HalfPlane` 表示 `dot(point-origin, normal) <= limit`。
`MissionConfig::light_stop_boundary()` 与越线检查共用同一几何，normal 由接近朝向计算，limit 取停车矩形
最前方角点的投影；支持旋转方向，不只限制世界坐标 x。

进入 `ApproachLight` 的当拍启用，`WaitGreen` 保持；只有原有停稳、新鲜绿灯帧数与保持时间条件
使任务转入 `Finish` 后才移除。边界变化立即清缓存路线，不重置转向状态。
入口完整足迹及实测速度停车圆盘在 `Reached` 判断之前检查；全局网格、全部曲率渐变连接、
局部扫掠足迹和候选停车圆盘也检查，因而不能靠“终点在线内”接纳中途越线的轨迹。
任务下一帧的越线 Fault 继续保留。

这一边界额外使用车体外接圆、网格半对角线和制动余量，可能拒绝勉强贴线的合法姿态。
它没有放宽比赛门限，也不是新的传感器障碍或虚拟雷达读数。场地和车体参数仍为合成值。
回归覆盖多种旋转方向、中途越线再返回、减速候选不能缩小停车圈、近停到达不能绕过停车检查、
旧路径失效，以及绿灯旧帧不能提前解除边界。

## 局部参考和诊断字段

`crates/robot-core/src/reference.rs` 提供 `PreparedReference`，每拍只验证一次完整路径。
各候选的最近点投影只扫描借用的局部窗口；兼容函数 `project_reference()` 供单次查询。
`cursor_to_end()` 按同一弧长原点向前采样真实路径尾部，不能把投影窗口边缘误当作真实终点；
超出真实路线才夹到末点，重复点跳过，非有限或倒退查询拒绝。
它在当前进度的入段及有界前方弧长范围内寻找局部投影，返回投影点、该折线段朝向、局部弧长及无符号距离。
末段按前方弧长预算截断，重复点跳过；距离相同时优先较早的弧长，减少交叉路径跳到较远后续支路的机会。
当前位置与候选端点使用相同的进度和预算，二者弧长之差才表示可比较的前进进度。

这份局部折线几何不包含规划器原生曲率，也不等于连续的 Frenet 参考样本。
新增投影不能被写成“已保留整条搜索轨迹的原始航向和曲率”；LQR 当前的局部参考估计边界仍然存在。

| 字段 | 解释 |
|---|---|
| `travel_boundary` | 当前灯前半平面，未启用时为 `null` |
| `selected_reference_cost_m` | 有朝向目标的整段平均参考误差；纯位置目标为 `null` |
| `route_revision`、`route_progress`、`route_points` | 导航缓存路径的版本、进度顶点及点数，帮助区分原路径上的阻塞与重新规划 |
| `tracking.mode` | 实际产生跟踪请求的算法，包括 LQR 低速回退后的 `pure_pursuit` |
| `tracking.lateral_error_m`、`heading_error_rad`、`reference_curvature_per_m` | LQR 本次已计算的误差与参考曲率；PP 或低速 PP 回退未计算这些量时为 `null`，不能按零误差解释 |
| `requested_curvature_per_m` | 跟踪器原始曲率请求，尚未经过本周期变化率约束 |
| `slew_limited_curvature_per_m` | 按上次指令和本周期变化率限制后的首选曲率 |
| `selected_curvature_per_m` | 最终候选选中的曲率；不存在选中候选时为 `null` |
| `selected_prediction_distance_m`、`selected_prediction_endpoint` | 最佳候选的普通预测距离和末端位姿，不是车辆已经走过的距离或反馈 |
| `selected_cross_track_m`、`selected_heading_error_rad`、`selected_progress_m` | 最佳候选在共用局部参考上的偏离距离、航向误差和前进进度 |

跟踪诊断位于 `crates/robot-core/src/tracking.rs`，导航诊断位于 `NavigationDecision.diagnostics`。
输入不合法或尚未产生跟踪结果时，部分诊断可以为空，不能据此补造数值。

`candidates` 记录本次调用的检查计数：

- `curvature_speed_limits`：在速度候选展开前，曲率对应的速度/制动限制已不满足；它按曲率计数。
- `near_zero_speed`：展开后的速度候选接近零，没有进入普通 rollout。
- `rollouts_evaluated`：实际执行 rollout 的次数。
- `accepted`：通过 rollout 的次数，不代表最终被选中，也不代表任务完成。
- `stop_reachable`、`grid`、`footprint`、`sample_budget`：分别表示停车可达圆盘、网格、足迹或采样预算导致的拒绝。
- `reference`：参考采样或代价出现无效值而拒绝，不能把未评分候选当作通过。

这些计数帮助解释 `no_collision_free_braking_trajectory`，不能只凭该字符串断言一定撞上了障碍物。
例如全部候选在速度门限处被拒绝时，`rollouts_evaluated` 可以为零。

## 首个异常窗口和存储开销

`crates/runner/src/navigation_diagnostics.rs` 是纯观察模块，`simulation.rs` 在每个模拟控制步调用它，
结束摘要新增 `first_navigation_failure`。没有命中触发条件时，该字段为 `null`。
触发条件为首次控制故障，或导航返回非 `task_stop`/`goal_braking` 的 `Blocked`。
无需先出现一次 Driving，启动阶段异常也能保留；正常任务停车不会消耗这一次记录机会。

模块最多保留 **8 帧前文 + 触发帧 + 8 帧后文，共 17 帧**。
每帧只包含时间、阶段、位姿、测量速度、命令、导航诊断和简短原因；不复制整条路径、图像、点云或张量。
原因字符串限制为 256 个 Unicode 字符。运行开头或结束附近出现异常时，窗口可以少于 17 帧。
后续普通停车超时不会覆盖最初窗口。当前只接入模拟/整场 A/B；Fault 结束主循环后，制动分支不会继续补满后文帧。

“首次异常”是定位问题的入口，并不自动证明它就是最终失败根因：某次阻塞可能稍后恢复，
整场仍可完成，也可能后来发生另一种故障。需要对照窗口、阶段变化、最终摘要和必要的显式 trace 继续判断。

窗口仅在内存维护，结束后随摘要交给已有输出通路；该模块自身不打开或写入文件，也不改变任何命令。
因此无需为首因分析默认开启逐帧磁盘 trace，不增加每 tick 刷盘。
eMMC 5.1 的擦写优化仍服从正常运行和比赛：不降低感知或控制频率、不因可选日志额度触发 Fault，
不调整车端挂载、swap 或 journald。必要诊断照常保存。

## 历史失败与本轮验收

修改前在提交 `8aceeaffb177af7630ae6e512a1f5ba38ac0dec7` 上重新运行原 LQR 全场模拟。
[修改前证据](motion-v2-before.json) 记录：17,400 ms 在绕锥桶阶段首先返回
`no_collision_free_braking_trajectory`，17,500 ms 随后出现 `no_forward_kinematic_path`，
最终 27,900 ms 因普通停车超过 10 秒失败，模拟终态速度为零。
这个序列说明只看最后的超时信息不足以解释最初停止的原因。
原始公开分享及完整逐帧日志留在本机 `work/`，Git 仅保存必要的复现摘要和局部证据。

本轮同一场景中 PP 在 55.9s 完成，原权重 LQR 在 53.3s 完成，终态速度均为零；
Rust常规237项、跟踪example 2项和交付34项通过，包含原导航11项及新增几何/诊断/灯线回归。完整数量、GLIBC/ELF 和交叉链接信息见[验证汇总](motion-v2-validation.json)。
前轮 PP 为 55.3s，LQR 为 27.9s 超时；当前单场合成秒数不能作为 CPU 性能或算法普遍优劣排名。
跟踪层 40ms 与整场 100ms 的旧基准差别仍保留，没有宣称已统一周期、噪声或执行器模型。

PP在14.3s曾出现一次可恢复阻塞，窗口保留17帧；LQR本轮没有触发窗口。这与两者最终完成相容。

当前没有接车、SSH、真实串口/相机读写或带动力测试，未在 RISC-V 目标或模拟器执行程序。
本地交叉链接基线仍为 `riscv64gc-unknown-linux-gnu.2.38`，没有安装或替换车端 GLIBC。
合成运动反馈不代替真实转向、制动、定位精度、延迟或 CPU 时延测量。
