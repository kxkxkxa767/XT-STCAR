## 软件与平台约束

p6 §3.2、p9–10 §4.4 指定北京小豚科技的标准平台，主控为 MUSE Pi PRO、8 核 64 位 RISC-V X60、8 GB/64 GB。
硬件表与本工程来源平台相符，但没有写 XT-STCAR 型号或完整改装许可，具体设备批次仍需核实。

**初稿未禁止 Rust，也没有明文要求必须使用 ROS2。** p6–7 将 ROS、SLAM、自主导航和传感器应用列为考察能力；
p6 §2.4.2(8) 明确禁止 ROS1 与 bag 工具，发现即取消比赛成绩。
需确认 bag 是否包括 `ros2 bag`、开发期采集/回放，以及本工程自定义 JSONL 诊断文件的适用范围。
当前 JSONL 用于离线测试，没有由此获得比赛许可；比赛车必须根据实时感知自主决策，不能用回放替代自主运行。

p6 §3.3 要求队员自行设计算法和运行方案，自主运行并禁止人工遥控。
Rust 核心、原生推理 C API 和必要 ROS2 接口的架构可以继续推进，语言本身不是初稿规定的障碍。

## 计时与会影响控制策略的处罚

p5：前轮压发车线开始计时，前轮过终点线结束计时。
有效时间 `T = 比赛用时 - 红绿灯停车用时 + 罚时`；运行分为
`80 × ((Tmax - T) / (Tmax - Tmin))²`，再加技术报告分。斑马线3秒不在明列的减时项中。

| 页码 | 行为 | 后果 |
|---|---|---|
| p5 | 撞锥桶 / 碰围栏 | 各+5 s；仅压锥桶支撑边角且不位移不罚 |
| p5 | 人行道前停不足3 s / 压线或越过后停车 / 未停车 | 分别+10 / +20 / +30 s |
| p5 | 绿灯未亮起就通行 / 任一车轮停在灯前区域外 / 未停车 | 分别+30 / +20 / +50 s |
| p5 | 除斑马线和红绿灯外，停止运行超过10 s | 本次任务失败 |
| p6 | 发车后遥控、切程序、设点、触车或人为改赛道/干预轨迹 | 每次+100 s；自主运行要求仍有效 |
| p6 | 终点四轮未全入区且未撞挡板 / 终点撞挡板 | 分别+5 / +10 s |

安全故障仍必须停车，不能为了避免“普通停车超过10秒失败”而自动清除 Fault 或恢复运动。
线上另要求三机位运行视频、赛道测量视频、技术手册及源码，视频不超过10分钟；有机位/尺寸/室外场地处罚，造假可取消资格（p7–9）。这里只记录规则，没有读取视频。

## 初稿中需要确认的事项

- p6 写线上人行道/灯具体位置赛前2周提供；p8 写所选赛道赛前1周公布，二者信息范围未明确区分。
- ROS1/bag 禁用的工具和阶段范围、是否必须采用 ROS2，以及允许改装范围未明文细化。
- p5 的 Tmin 文字解释不完整；Tmax=Tmin 时公式分母为零，未完赛如何计分、罚时对统计集合的影响需确认。
- 重叠处罚是否累加、停车测量阈值、红灯停车减时起止点、终点容差均未明确；灯图包含黄灯而正文只有红/绿行为。
- p8 图中是尺寸范围，不能作为唯一精确地图；p7“编码器等”是能力举例，不证明实车有编码器。
- 线下材料文字含视频/宣传内容但示例目录只列手册/源码（p7）；p10 电机“最大转速40km/h”量纲不一致，不能转换为控制参数。

当前仍暂不接车。已有协议、串口和离线回放是参赛基础，实际感知、定位、任务执行与物理停车仍需逐项完成验收。
