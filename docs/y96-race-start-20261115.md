# y96／203 比赛起步调整

y95 两次发车均被助手的旧控制台预检查拒绝，没有启动比赛程序。两次雷达均为 346/360 个有效点，雷达数据年龄 56.85/53.17 ms，唯一质量问题是 `front_sparse`：正前连续缺测 13/12°，超过旧门槛 3°。两侧挡板回波正常；缺测的具体物理原因尚不能由这些记录单独确定。

后续只读取了一帧现场雷达和相机。该帧为 seq8814，343 个有效点；原始点云有两侧墙，但旧格式的 `wall_candidates`、`corridor_candidates` 均为空。现有两侧拟合各有 51 个支撑点，3 cm 内点均为 51，残差中位数约 2.2/4.4 mm。不能因此说没有可用方向信息。

## 改动

- 助手保留在线、锁车和占用检查，取消重复的旧道路预览拒发条件，由 Rust 比赛程序用实时数据决定发车。
- 比赛标志在等待发车前就设置。比赛起步及起步直道不再以“至少342个点”“正前缺测最多6个、连续最多3°”拒绝；缺测原样记录在 `start_coverage_observed`，不伪造回波或自由空间。
- 比赛起步取消“前方必须有至少1 m回波”和固定0.65–2.2 m宽度范围。仍按实测两侧墙确定方向与车身空间。
- 无旧格式墙标签时，复用既有两侧原始点拟合补充起步段航向，沿用罗盘的模90°与角速度更新方式，不写死零航向。
- 原Guard、控制/雷达新鲜度、已观测8 cm近障以及空扫描拒绝保留。其他赛段原有质量恢复逻辑继续使用；y95的2.8 m临时斑马线预设、固定等灯10 s和逐帧采图继续保留。

## 验证

46项Rust检查通过，含现场点云回放、部分覆盖变体、启动应答接续到行驶，以及5 cm近障/过期/空扫描仍拒绝。这里的行驶指令是离线模拟应答下的内存输出，没有发往车辆。另通过7项已有引擎代理检查；clippy程序/测试目标33/35条既有警告，没有新增全赛道仿真。

证据在 `work/codex-y95-start-rejection-20261115/`；雷达图为 `current-lidar-front-gap.png`。当前点云回放样本已作为回归夹具保存，控制逻辑没有引用这个场地的数据。
