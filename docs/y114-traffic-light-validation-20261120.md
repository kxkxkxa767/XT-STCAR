# y114 红绿灯识别与历史照片验证

2026-11-20。当前实车记录为 y113／218。本次在 Mac 上把新增的 Rust 灯色检测器、现用 mix 模型和两者的融合结果逐帧对照，并测量了同一相机帧到两路结果的时间。

## 按实车轮次留出的验证集

12 轮共 512 张原始 JPG。开发阶段另用了更早或更晚的其他轮次，包括已经取回的 y113 七轮。确定检测参数后才对这 12 轮运行最终比较。按照片可见的点亮灯芯标注，保留熄灯灯罩、无灯画面、顶部裁切的灯头、红色围带及反光。12 轮共享部分赛道和灯具，停车时还会连续拍到同一灯头。

其中 199 张亮红灯、27 张亮绿灯、274 张没有可辨认的亮灯。另有 2 张切换帧同时拍到两色，10 张因户外照明或镜面反光难以确定，逐帧表单列。以下分母共 500 张。YOLO 使用 y113 的 mix 模型，以发布阈值 0.25 统计单帧颜色。两色同时出现时按红色统计。运行中的绿灯放行还使用原有的新鲜度、分数和两帧确认。

| 识别方式 | 红灯检出 | 绿灯检出 | 无亮灯帧误报 |
| --- | ---: | ---: | ---: |
| mix YOLO | 146/199（73.4%） | 27/27 | 7/274（5 红、2 绿） |
| 纯 Rust | 197/199（99.0%） | 27/27 | 0/274 |
| Rust 与 mix YOLO 融合 | 198/199（99.5%） | 27/27 | 7/274（5 红、2 绿） |

y68 停车时红灯芯被画面上沿截断，Rust 补回了 YOLO 的漏检。y74 的第 58 帧由 YOLO 补回，两路共同漏掉的是 y71 的第 58 帧。融合的 7 张误报都来自 YOLO。逐帧比较也纳入了起步和绕桶的原图，实际比赛只在灯区接入 Rust 判色。这些数字描述照片上的结果。

另用比赛场地视频留存的 7 张抽帧做背景检查。每张取下部 4∶3 区域并缩放到 640×480，包含红蓝地面、白线、积水反光。Rust 和融合均为 **0/7** 误报。原始抽帧来自同一段场地视频。这组照片只验证红色场地干扰，明确点亮的红绿灯正例主要来自室内。

## 同一帧到结果的耗时

在 Apple M5 上按 512 张原图顺序回放。实际相机程序读取 JPG 完成后记取帧起点，发布原尺寸 BGR，并在 ONNX 推理前通过本机数据报唤醒正式 Rust 灯色线程。Rust 终点为观察方收到结果，YOLO 终点为生成灯色状态。单 YOLO 对照使用旧灯区四线程配置。数据来自文件回放，相机曝光和下游控制节拍在测量区间之外。

| 本机路径 | 中位 | P95 |
| --- | ---: | ---: |
| 单 YOLO，灯区 4 线程，取帧到生成灯色 | 5.20 ms | 5.40 ms |
| 并行方案，取帧到 Rust 回报 | 0.42 ms | 0.53 ms |
| 并行方案，同一帧取帧到 2 线程 YOLO 生成灯色 | 5.03 ms | 5.32 ms |

Rust 收到 512/512 帧，全部先于同帧 YOLO 回报。在 226 张可判定的亮灯照片中，224 张由 Rust 提前给出正确灯色，1 张由 YOLO 补回。Rust 像素计算本身的中位约 0.13 ms。采集继续使用现有的相机循环，下一次取帧仍受该循环的推理速度影响。

作为板端参考，已取回的 y113 七轮中，灯区四线程 YOLO 共 163 帧，推理中位 230.4 ms、P95 375.1 ms。y114 首次实车运行后，灯区的 `run/rust-light.jsonl` 会给出实际绑核、计算耗时，以及从取帧到 Rust 发出结果的时间。当前没有 y114 的板端实测时延。

## 比赛程序接入

- Rust 在画面上部搜索紧凑灯芯，检查外围多个方向的暗色灯壳。过曝白芯通过周围的红、绿光晕判色。饱和色块另外检查形状和四角，降低红色板面、地面和不发光灯罩的干扰。
- 三个天气入口都在灯区开放同一份相机原帧。灯区 YOLO 从 4 线程降到 2，其他阶段继续按原来的线程数运行。Rust 灯色线程请求 CPU 3，灯区以外阻塞等待。共享帧通知失败时仍能读取最新已发布帧，退出时清理通知套接字。
- 同一相机帧在两路使用相同编号。Rust 的有效颜色可先送入控制器，YOLO 可补充同一帧。一个编号只占一个灯色历史位置，较旧帧不覆盖较新帧。已收到的同帧红色会阻止该帧充当绿灯放行依据。灯区沿用两帧新鲜绿灯和既定 10 s 放行规则。
- 主目录保留纯识别与 N10P，`test/` 保留固定 2.8 m 与 N10P，`提交/` 保留纯识别与 N10。软板发车容差、端线测距回退、Guard 和 8 cm 车身门沿用既有实现。

## 复算

在工程根目录运行以下命令。输出目录应为一个新目录。脚本使用仓库中的实际 Rust 像素检测代码，并用指定模型重跑这 512 张照片。

```sh
.venv-model/bin/python -B scripts/evaluate-traffic-lights.py \
  --model-dir work/vehicle-dynamic-deploy-20261008/weather-y113-eec7c2a/models/mix \
  --out work/traffic-lamp-recheck
```

逐帧记录包含原轮次和文件名、观察色、两路分数或判色以及融合结果。原始照片保存在各轮证据目录的 `vision/frames/` 下。[逐帧数据](y114-traffic-light-frames-20261120.jsonl)
