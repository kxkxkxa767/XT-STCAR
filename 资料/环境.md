## 2. 环境选择

### 语言选择：优先 Rust

Muse Pi Pro 可运行 C++ 和 Rust。用户已选择优先 Rust，新控制逻辑、状态机和协议模块采用 Rust；
厂商 C++/Python 传感器与 YOLO 节点可以继续使用，通过 ROS 2 消息互通。

[Rust 官方 RISC-V Linux 目标说明](https://doc.rust-lang.org/rustc/platform-support/riscv64gc-unknown-linux-gnu.html)
提供 `riscv64gc-unknown-linux-gnu`，支持在 RISC-V 主机开发，也支持安装目标标准库用于交叉编译。
Linux/ABI/外部动态库仍须核实。`rustup target add` 不会安装 RISC-V C 链接器或车端 ROS 库，
因此仅安装该组件不能宣称已完成车端程序交叉编译。

[rclrs 上游说明](https://github.com/ros2-rust/ros2_rust) 提供 Rust ROS 2 接口和 Humble/Jazzy
构建指引；接口仍演进，厂商定制 RISC-V 环境必须实测，锁定可用提交和消息生成依赖。
先做纯 Rust 核心库，再验证简单 ROS 发布订阅，最后接底盘与视觉结果。
不在本机无 ROS 环境时直接安装整套 rclrs，也不把它声称为已完成 ROS 集成。

本机已有 Rust/Cargo 1.97.1、rustfmt 和 clippy，host 为 `aarch64-apple-darwin`。
可执行文件在 `/Users/yuhaojin/.cargo/bin/`，工具链由 `/Users/yuhaojin/.rustup/` 管理，
它们是用户公共环境，不在工程目录。未改变全局默认 Rust 版本。

```bash

```

Windows 队友通过 [rustup 官方入口](https://rustup.rs/) 安装 Rust；

```powershell
# wsl --install -d Ubuntu-24.04
```

新版本 Windows 支持范围、安装异常和网络配置以 Microsoft 文档为准。

| 车端实际环境 | 主机 ROS 环境候选 | 要核对的兼容性 |
|---|---|---|
| 厂家 Noble + 定制 Humble | WSL Ubuntu 22.04 + 上游 Humble | 消息定义、RMW/DDS、厂商补丁；不是相同 Python ABI |
| 厂家确认 Jazzy | WSL Ubuntu 24.04 + Jazzy | 同版本消息与依赖 |
| 尚未确认 | 先 SSH 到车端工作 | 暂不在 Windows 锁定 ROS 发行版 |

[Humble 官方发布说明](https://docs.ros.org/en/humble/Releases/Release-Humble-Hawksbill.html)
对应标准 Ubuntu 22.04；厂商在 Noble 上移植 Humble 是另外的环境，不能直接混装其依赖。
例如 Ubuntu 22.04 的 ROS Python 使用发行版配套 Python，不强制替换为 3.12；
车端 Python 版本则按其 ROS 构建决定。跨机器 ROS 消息通信与复制 Python 二进制扩展是两回事。

WSL 中基础 Linux 开发包候选（在 WSL Ubuntu 内执行，不在 PowerShell 或车端盲跑）：

```bash
sudo apt update
sudo apt install build-essential cmake ninja-build pkg-config git openssh-client rsync python3-venv
```

ROS 按所选发行版官方说明安装；本轮不配置软件源或远端 Windows 系统。
工作空间放在 WSL 自己的 Linux 文件系统中，例如 `~/projects/XT-STCAR`。
WSL/虚拟机若不能发现车端话题，检查局域网可达性、DDS 发现、ROS_DOMAIN_ID 和防火墙；
先用 SSH 车端检查，不把“SSH 能通”当作 ROS 多播一定可用。

上传脚本默认 dry-run，账号/IP/独立新 release 目录均需显式填写；本轮未执行上传。
详见 [部署包使用说明](../docs/部署包使用说明.md)。

直接链接 C++、ROS、OpenCV 或厂商推理 C 库时，仍需要匹配 ISA/ABI、glibc 及对应目标库/sysroot。
不能用旧 `aarch64-unknown-linux-gnu` 或 STM32 裸机 ARM 编译器生成 Muse Pi 程序。
厂商 SDK 若仅支持 Linux 主机，应使用匹配构建环境；Windows/WSL 交叉环境本轮未验收。

YOLO26n 已实现 Rust 预处理/后处理、CLI、默认原生 ORT 后端、可选 Python 参考后端及导出/校验工具。
机器人模块另含传感器语义、安全状态机、底盘抽象输出、图像事件输入、总调度与日志，已完成整链路回放。
模型接口锁定 Ultralytics 8.4.142 的 one-to-one Detect；真实模型验收状态见验证记录，
版本语义与环境复现方法见 [YOLO26 接口](../docs/YOLO26接口.md)。
不能把已有 YOLO11 厂商示例当作 YOLO26n 兼容或帧率证明。

STM32 固件属于另一套构建：核实完整芯片型号、厂家工程和下载器后再选 CubeIDE/CubeCLT、
Arm GNU Toolchain 或厂商指定环境。现有 STM32 工具保留，但本轮不刷固件。

## 3. 首次接入只读清单

YOLO 方面，官方提供 YOLOv5/v6/v8/v11 的 ONNX 与 ROS 2 部署示例，
见 [归档原文](官方参考/进迭时空_YOLO部署_原文.md)。车端示例使用 `python3-spacemit-ort`；
本机已在独立模型环境完成 YOLO26n 导出与主机参考推理。车端既有权重仍需核对模型版本、ONNX 算子、预处理与后处理，
再实测新车延迟和精度；不能把厂商预训练示例支持等同于所有自训练模型即插即用。
示例中出现 `/opt/bros/humble`，其他安装页使用 `/opt/ros/humble`，必须以实机路径为准。

先取得新车 IP 和账号，经 SSH 登录。以下命令在车端执行，记录结果，不预设旧车设备名：

```bash
uname -m
cat /etc/os-release
dpkg --print-architecture
python3 --version
command -v gcc g++ cmake colcon ros2
ls /opt/ros
printenv ROS_DISTRO
ip -br addr
lsusb
ls -l /dev/serial/by-id/ /dev/v4l/by-id/
systemctl --type=service --state=running --no-pager
```

目录或命令不存在也是有效调查结果；不因此自动安装或更换系统。
若 ROS 已安装但当前 shell 未加载，核实实际发行版后读取其 setup 文件。
已加载环境可继续只读查看：

```bash
ros2 node list
ros2 topic list -t
ros2 service list
ros2 pkg list
```

不要在首次调查阶段执行 `ros2 topic pub`、底盘 launch 或固件烧录。
确认实际话题后再检查 `/scan`、图像、IMU、里程计与 TF；名称可能不同，不当作既定接口。
